# 0x091 时间戳抖动修复报告（2026-10-15）

## 一、测试现象

1000Hz CAN 推送时，0x091（时间戳报文，小端 uint64，单位 us）相邻包时间戳差值
（包2-包1）在 **0.8~1.2ms** 之间波动（步进 0.1ms），长期均值恰为 1ms。理论上应为 1ms。

## 二、根因分析

时间戳产生链路（修复前）：

```text
SysTick_Handler (1ms硬件节拍, gd32f30x_it.c)
  └─ BspSysTickMs()                 ← 仅 RunFlag=1、RunSysTicks++
主循环 1kHz 分支 (bsp_function.c, RunSysTicks % RUN_1000Hz == 0)
  ├─ SensorSystem_ReadData() / BspSensorDataProcess()
  ├─ BspSysRunTimeSet(DWT差值)      ← ★ G_SysRunTime 在此累加
  └─ check_and_send_message() / BspUserDataPushControlCenter()
       └─ 0x091 打包读取 BspSysRunTimeGet()   (bsp_data_interaction.c)
```

**根因**：`G_SysRunTime` 的递增时刻 = 主循环执行到 1kHz 分支的时刻，而非硬件节拍时刻。
主循环执行相位受单圈耗时波动（指令解析、推送、CAN 入队、Flash 处理）影响，
绕 SysTick 边界漂移达 ±200us。DWT 差值累加如实记录了"相邻两圈的真实执行间隔"：
某圈巡回晚 → 差值 >1ms，下一圈补偿 → <1ms（0.8+1.2=2.0ms 的配对特征）。
DWT 方案无累积误差，故均值精确 1ms——与测试现象完全吻合。
**不是 CAN 发送问题，是时间戳源的锁存位置问题。**

## 三、方案对比与选型

| 方案 | 分辨率 | 相邻差值 | 结论 |
|------|--------|----------|------|
| 原实现：主循环 DWT 累加 | 1us | 0.8~1.2ms 波动 | 抖动源为主循环巡回延迟 ±200us |
| SysTick ISR 内 `+= 1000` | 1ms | 严格 1000us | 分辨率退化，无法满足 us 级对齐需求 |
| **选定：SysTick ISR 内时基差值累加（时基源由主工程注入）** | **1us** | **≈1ms ± 中断响应延迟（通常 <±50us）** | 抖动缩小一个数量级，分辨率保留 |

选型依据：读数点移入 SysTick 中断后，抖动源从"主循环巡回延迟（几百 us）"
收敛为"中断响应延迟（几 us～几十 us，仅被 CAN TX 等高优先级中断抢占时出现）"；
DWT 换算同源（核心时钟），PPS 频偏校准（G_SlopeA/G_SkewingB）语义不变。

## 四、修改清单

| 文件 | 修改 |
|------|------|
| `bsp/00.Code/inc/bsp_run_ctrl.h` | 新增 `BspUsTimeSource_F` 时基源函数指针类型（返回上电以来绝对微秒，32 位回绕）与注册接口 `BspSysUsTimeSourceRegister()` |
| `bsp/00.Code/src/bsp_run_ctrl.c` | **移除 `#include "dwt.h"`**（bsp 子仓库为共用代码，不得直接依赖 MCU 底层接口）；`BspSysTickMs()` 内改为经注入时基源差值累加（`G_LastUs` 基准 + `G_UsBaseValid` 首拍标志，无符号减法天然处理 32 位回绕）；`BspSysRunTimeReset()` 同步清基准有效标志 |
| `system/main/main.c`（主工程） | 新增 `SysUsTimeSourceGet()`（`dwt_us_from_cycles32(dwt_cycles32())`，DWT 周期→绝对微秒）；`dwt_timer_init()` 后调用 `BspSysUsTimeSourceRegister(SysUsTimeSourceGet)` 完成注入 |
| `bsp/00.Code/src/bsp_function.c` | 删除 1kHz 分支 DWT 累加（`CycleNow`/`LastCycle1ms`/`BspSysRunTimeSet` 共 7 行）及已无用的静态变量 `LastCycle1ms`；200Hz/100Hz 分支的 `last_clock_us`（算法 dt 测量）不受影响 |

依赖注入架构（bsp 共用代码与 MCU 底层解耦）：

```text
主工程 main.c（平台相关）                bsp 子仓库（共用,平台无关）
┌────────────────────────────┐         ┌────────────────────────────────────┐
│ dwt_timer_init()            │         │ BspSysTickMs()  (SysTick 1ms ISR)  │
│ SysUsTimeSourceGet()        │─注册注入─▶│   UsNow = G_UsTimeSource()          │
│  = dwt_us_from_cycles32(    │         │   G_SysRunTime += UsNow - G_LastUs │
│    dwt_cycles32())          │         │   (us级时间戳,首拍建基准)            │
└────────────────────────────┘         └────────────────────────────────────┘
```

自愈设计：时基源注册晚于 SysTick 使能时，未注册期间不累加，注册后首拍自动建基准，
无累积误差；`BspSysRunTimeReset()` 复位后同样下一拍重建基准。

## 六、时间戳修改规范（后续约束）

1. `G_SysRunTime` 的累加**只允许**发生在 `BspSysTickMs()`（SysTick 1ms 中断）内
2. 禁止在主循环任何位置调用 `BspSysRunTimeSet()` 累加时间（该 API 保留但不应使用）
3. 0x091 等时间戳消费方只读 `BspSysRunTimeGet()`，不做二次补偿
4. 复位时间必须走 `BspSysRunTimeReset()`（已封装基准清理），不得直接写 `G_SysRunTime = 0`
5. bsp 子仓库共用文件**禁止**直接包含 `dwt.h` 等 MCU 底层头文件或调用底层接口；
   底层能力一律由主工程经函数 API 注入（如 `BspSysUsTimeSourceRegister()` 注册时基源）
