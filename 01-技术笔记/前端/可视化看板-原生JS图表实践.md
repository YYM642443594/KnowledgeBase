# 可视化看板-原生JS图表实践

## 概述

本文档总结用原生 JS/CSS 给静态页面加「数据看板」的实践（源自 demo_zsk 知识库说明网页）：什么情况该用图表、什么情况只该用统计卡，条形图的画法规范，以及悬停提示与无障碍处理。零依赖、双击可打开的场景同样适用。

## 正文

核心结论：**先选形式再配色——单个数字用统计卡，"比大小"用单色条形图；配色必须跑校验脚本而不是靠眼睛；tooltip 只做增强，数值必须有表格视图兜底。**

### 形式选择：先问数据的任务

| 数据的任务 | 用什么 | 不要用 |
|------|------|------|
| 单个当前值（分类数、文档总数） | 统计卡（label + 大号数值） | 单根柱子的"柱状图" |
| 少数几个头条数字 | 一排统计卡（KPI 行） | 分组柱状图 |
| 各分类的数量比较 | 横向条形图 | 饼图/环形图 |
| 一个比例（如覆盖率 3/9） | meter 进度条 | 双片饼图 |

本次看板：4 张统计卡（分类/文档/标签总数 + 覆盖分类 meter）+ 两张横向条形图（各分类文档数、标签频次）。

### 配色：单色 + 脚本校验

- 条形图只有一个度量（文档数），**整图一个色相**，不要每根条换一个颜色——颜色在这里不承载"身份"信息，逐条换色是误导性装饰；第二个图表上下文（标签频次）才换下一个色槽；
- 本次用蓝 `#2a78d6`（分类图）和橙 `#eb6834`（标签图），白底。是否色盲安全、对比度是否达标**用脚本验证**（如 dataviz validate_palette 脚本），不要目测；
- 文字永远用文本色（主/次/弱化），**数值和标签不穿系列色**，系列色只出现在条、线、点本身。

### 条形图画法规范

```css
.hbar-fill {
  height: 18px;                      /* 细条，≤24px，不撑满行 */
  border-radius: 0 4px 4px 0;        /* 数据端 4px 圆角，基线端方角 */
  background: var(--bar-color);
}
.hbar-track { padding-right: 30px; }  /* 给条端数值留位，满条不溢出 */
```

- 横向条形图天然容纳长分类名，比竖向柱状图更适合中文标签；
- 每根条按值排序展示；条与条之间留 ≥2px 表面间隙（本例行间 7px）；
- **数值放条端**（bar 直标的文档化位置），全部直标后可省略坐标轴和网格线；
- 满值条（100% 宽）后面跟数值文字会溢出：给轨道 `padding-right` 预留数值宽度，比例基准对所有条保持一致，不失真。

### tooltip 与无障碍

- tooltip 用 DOM + `textContent` 构建，**内容不进 innerHTML**（标签名是不可信数据）；
- 命中目标是**整行**而不是 18px 的条本身（pointermove 绑在行上），悬停行加背景色反馈"已响应"；
- 键盘可达：行设 `tabindex="0"`，`focus` 时显示与悬停相同的 tooltip，`blur` 隐藏；行带 `aria-label="分类名：N 篇"`；
- **tooltip 只增强、不独占**：条端已有直标数值，每张图还配 `<details>` 表格视图孪生，不悬停也能读到全部数值（表格数字列用 `font-variant-numeric: tabular-nums` 对齐）。

### 关键点

- 统计卡与图表的分工：一个数就是卡，比较才是图；
- 单一度量的条形图整图单色；配色过校验脚本；
- 细条 + 数据端圆角 + 条端直标 + 充足留白，比粗壮色块更易读；
- tooltip/键盘焦点/表格视图三层兜底，数值永不依赖单一通道。

## 总结

零依赖也能做出规范的看板：形式选择 → 单色校验 → 标记规范 → 交互兜底，四步都是纯 CSS/JS 可达的。数据量增长后若需要折线、面积、交叉筛选，再考虑引入图表库，并沿用同一套配色与无障碍约定。
