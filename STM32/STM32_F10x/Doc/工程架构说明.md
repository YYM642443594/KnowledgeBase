# 工程架构说明（STM32F103C8T6）

> 本文描述工程**当前**的架构全貌：目录组织、三层依赖规则、关键运行机制。历史演变见 [架构调整-四层改三层](./架构调整-四层改三层.md) 与 [三层架构重构完成记录](./三层架构重构完成记录.md)；逐维度检查标准见 [Project_Level_Skill 架构规范](../Project_Level_Skill.md)。

## 工程概览

- 芯片：STM32F103C8T6（Cortex-M3, 72MHz, 64KB Flash / 20KB RAM）
- 工具链：Keil MDK + ARMCC V5.06
- 当前尺寸：Code=25308 / RO=4256 / RW=716 / ZI=7548（0 Error / 0 Warning）
- 自研代码全部在子仓库 `bsp_ptj_module` 中（主仓以 submodule 方式引用）

## 三层架构与依赖规则

```text
APP  (app_main / app_parse_* / app_func / app_cloud / app_car / app_display / app_clock / app_param)
  │  仅允许向下调用
  ▼
DRV  (drv_* 器件驱动：sensor/flash/无线/总线器件约 40 个模块)
  │
  ▼
HAL  (hal_uart / hal_timer / hal_systick / hal_exti / hal_can / hal_usb / hal_spi / hal_iwdg / hal_spi)
  │
  ▼
厂商库 (CMSIS / StdPeriph / USB_ST_LIB)
```

依赖规则（违规即规范不合规）：

1. **严格单向**：APP→DRV→HAL→厂商库，禁止任何反向 include 或调用；
2. **APP 禁直调 HAL**：跨层须经 DRV 薄转发层（类型引用如 `DRV_xxx_OK` 枚举豁免）；
3. **BSP 为板级兼容层**：仅 `bsp_config.h`（机型配置表 `BSP_CFG_HW_MODEL`）+ `bsp_board`（板级初始化 + 1ms 节拍），禁调 DRV/APP；
4. **厂商库区豁免**：`00.STM32/` 下三个厂商目录不参与分层/命名检查，业务代码不进入；
5. **层级无关配置**：`cfg_modules.h` 任何层均可包含（纯宏定义，不构成依赖）。

## 关键机制

### 1. 时间片轮询调度（裸机无 RTOS）

SysTick 1ms 节拍 → `bsp_board` 毫秒计数 → `AppProcess()` 频率槽分发：

- **取 tick 快照**是关键：进入函数时一次性读取节拍计数，前序槽阻塞推进的计数不影响后续槽判定，否则 1Hz 槽条件永假、慢任务被系统性饿死；
- 三档频率槽，快任务在前慢任务在后：**100Hz**（AT 解析/红外/GPS）→ **10Hz**（超声波/小车状态机/OLED）→ **1Hz**（传感器采样/云连接）；
- 长阻塞任务（云连接数十秒 AT 交互）放 1Hz 槽尾，阻塞前其余任务已完成，属有界阻塞可接受。

### 2. 中断分发链（分层转发）

```text
stm32f10x_it.c 向量函数  →  HalXxxIrqHandler()  →  注册回调（APP 业务）
```

- 向量层只做一行转发，不含业务逻辑；
- HAL 层处理清标志/缓冲搬运，再分发到 APP 通过 `XxxInit` 注册的回调函数指针；
- CAN/USB 等可裁剪模块的中断向量用 `#if APP_MOD_xxx` 包裹——置 0 时向量消失，链接器把整条链路（hal/drv/厂商库函数）全部剔除。

### 3. 回调注册模式（解决"下层如何通知上层"）

分层禁止 DRV 直接调用 APP 函数，但"串口收到字节→AT 解析"天然是下层产生的事件。解法：**上层向下层注册函数指针，注册动作本身是合法的向下调用**。

```c
/* APP 层初始化时 */
DrvUartSetRxCallback(UART_CH_AT, AppParseOnByte);   /* APP→DRV 注册 */

/* DRV 层中断上下文中经函数指针回调 APP，无反向依赖 */
```

### 4. AT 指令解析（按域拆分）

`app_parse.c` 做分发（指令表 + 通道路由：UART1/UART3/USB CDC），具体指令处理按业务域拆到 `app_parse_<域>.c`（motion/param/sensor/env/imu/gps/ir/rtc/io/fp/rfid/w25q64/apds/dot 等十余个）。新增指令域 = 新增一个 `app_parse_x.c` + 注册进指令表，不动分发框架。

### 5. 编译期功能裁剪（cfg_modules.h）

原理：ARMCC 链接器默认 `--remove`，未被引用的函数不进镜像。`#define APP_MOD_xxx 0/1` 置 0 后各调用点（`#if` 包裹）引用消失，整组代码被链接器剔除，无需从工程移除文件。

- **互斥守卫**：`#error` 强制编译失败（三云平台共用一个 ESP-01S 串口互斥；USB 与 CAN 共用 PA11/PA12 和 USB_LP 向量互斥）；
- **依赖守卫**：硬依赖编译期检查（`CAR requires MOTOR`、`LCD1602 requires PCF8575`），模式级软依赖运行期拒绝；
- **实测裁剪效果**：关阿里云组约省 20KB，关 CAN 组约省 2.5KB；
- 机型差异（引脚/串口绑定）由 `bsp_config.h` 的机型宏体系决定，与功能裁剪两级独立。

### 6. 云平台多后端（编译期选择）

`app_cloud.c` 对外接口平台无关（`AppCloud*`），后端由 `APP_MOD_ALIYUN/BEMFA/ONENET` 编译期互斥选择。平台相关实现函数带前缀（`Aliyun*/Bemfa*`），后续接入新云 = 新增后端分支，上层调用不变。

## 命名规范

| 类别 | 规则 | 示例 |
|------|------|------|
| 函数 | 模块前缀 + 大驼峰 | `AppParseOnByte` / `DrvLedCtrl` / `HalUart1IrqHandler` |
| 类型 | `_S` 结构体 / `_E` 枚举后缀 | `AppParam_S` / `AppCloudState_E` |
| 文件级全局 | `G_` 前缀 + static | `static AppCloudState_E G_State` |
| 宏 | 全大写下划线 | `APP_MOD_BEMFA` / `DRV_SERVO_MAX` |
| 厂商契约豁免 | libc 钩子与 ST 库按函数名调用的函数保留原名 | `_sys_exit` / `fputc` / `USBCableConfig` |

## 新增模块的标准动作

1. `src/drv_xxx.c` + `inc/drv_xxx.h`（器件驱动，只依赖 HAL）；
2. `cfg_modules.h` 增加 `APP_MOD_XXX` 开关 + 注释说明依赖与引脚；
3. 业务指令加 `app_parse_x.c` 或现有域文件，注册指令表；
4. 中断依赖则在 `stm32f10x_it.c` 加 `#if` 包裹的向量转发；
5. uvprojx 添加文件，全量 Rebuild 验证 0 Error / 0 Warning。
