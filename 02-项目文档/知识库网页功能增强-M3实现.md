# 知识库网页功能增强（M3 实现）

> 记录 `kb-viewer-template.html` M3 功能增强（双主题 / 文档页头重设计 / 阅读辅助 / 打印与 favicon）的实现要点与关键取值，承接 [知识库网页视觉进阶（M2 实现）](知识库网页视觉进阶-M2实现.md) 与 [M1 基线](知识库网页视觉设计规范-M1基线.md)。完整改动以模板文件为准，本文记录「为什么这么做」与「坑」。

## 结论（M3 改了什么）

- **浅色主题 + 亮/暗切换**：默认深色；顶栏新增太阳/月亮切换按钮（SVG），`data-theme` 属性驱动浅色令牌组，`localStorage`（键 `kb-theme`）记忆，`<head>` 内预置脚本首帧前落位避免闪烁；
- **文档页头重设计**：面包屑改为「首页 / 分区 / mono 路径胶囊」，元信息行（更新 / 创建 / 大小 / 标签 chips）只渲染数据真实存在的字段；hero 仓库/分支胶囊改为 `KB.repo`/`KB.branch` 数据驱动（现管线未下发，走回退值）；
- **阅读辅助**：目录 scrollspy 高亮项自动滚入目录视野；侧栏次级小字（搜索片段 `.sub`、提交日期 `.cd`）对比度提升；`<1450px` 目录改右侧抽屉 + 左下角 FAB 入口（遮罩 + `--t-med` 滑入，与移动端侧栏同款模式）；
- **打印样式 + favicon**：`@media print` 隐藏顶栏/侧栏/目录/搜索，代码块与表格完整可读且避免内部断页，外链附 URL；favicon 用内嵌 SVG data URI（渐变圆角方块 + 菱形 logo，零外部请求）。

## 关键实现要点

### 1. 双主题（令牌换值，选择器零新增色值）

- 浅色令牌由 M1 深色令牌**同色相派生**：`--bg #f3f5fa`（页面）/`--bg2 #ffffff`（卡片、侧栏、代码块）/`--bg3 #e9edf5`（输入框、表头）/`--fg #28303f`，正文字色对比度 ≥4.5:1；`color-scheme` 同步切换原生控件渲染；
- M2 语法高亮的 `k/n/c/p` 本就引用令牌（accent2/orange/fg-faint/accent），随主题自动切换；`s`（字符串绿）与 `f`（函数紫）是深底提亮字面值，本轮令牌化为 `--tk-s/--tk-f`，浅色取 `#147a4d`/`#7d3fc4`（白底 ≥4.5:1）。**浅色代码块取法：浅色化代码块背景（`--bg2` 白底）+ 分词色同步换深字值**，弃用「深底代码块保留」方案——整页白底嵌深块观感割裂，且浅字值一并协调后可读性实测更优；
- 首轮实现把 `#tocfab.on{display:flex}` 写在了媒体查询外，导致桌面端 FAB 误显示——位置敏感的显隐规则必须整体放进对应 `@media` 块（已修复，截图核验通过）。

### 2. 阅读辅助

- scrollspy 在切换 `.on` 后对当前项 `scrollIntoView({block:'nearest'})`——只滚动 `#toc` 自身（最近可滚动祖先），不牵动正文；仅当目录可见（`.show`）时执行；
- 侧栏对比度只动局部选择器（`.nav-item .sub`、`.commit-item .cd` → `--fg-dim`），不改全局 `--fg-faint` 令牌值（M1 评审建议的原话）；
- 目录抽屉：`<1450px` 时 `#toc` 从「右上悬浮」切换为「右缘抽屉」（`transform:translateX(105%)` ↔ `.open`），桌面态的 `.show`（内容存在性）与抽屉态的 `.open`（用户打开）**语义分离**，避免「有目录的文档页在窄屏默认全开」的冲突；FAB 仅在 `buildTOC()` 判定 ≥3 个标题时加 `.on` 显示；打开抽屉自动收起移动端侧栏，反之亦然，防双抽屉叠开。

### 3. 打印与 favicon

- 打印对代码块/引用/表格/图片 `break-inside:avoid`（超页高的代码块浏览器会强制分页，不裁内容）；外链 `::after` 追加 `(url)` 便于纸面溯源；`print-color-adjust:exact` 保底浅灰代码底色；打印样式全部写死浅色值（纸张即白底，与主题无关）；
- favicon：`<link rel="icon" href="data:image/svg+xml,…">`，64×64 渐变（`#4f8cff→#9b6ce0`，即 `--grad` 同源色）圆角方块 + 白色菱形，单文件零请求。

## 坑（本轮新增，后来者必读）

1. **模板注释里不得出现任何占位符字面量**（如 `__KB_DATA​__`）：`kb_build_viewer.py` 的 `tpl.replace(占位符, json)` 是**全量替换**，注释里出现一次就会把 7MB JSON 再注入一份（本轮实测产物翻倍至 14MB）；占位符自检（`build_once` 尾部）也会因此报 `BUILD_FAIL`；
2. **文档正文含占位符字面量同样引爆管线自检**：M2 实现文档正文里写了 `__KB_DATA​__` 字面量，M2 提交后任何一次重建都会把它嵌进产物 JSON，管线自检 `if "__KB_DATA​__" in html` 恒真 → `BUILD_FAIL` → 自动同步停摆。本轮已在 M2 文档中以零宽空格（U+200B）断开该字面量（显示不变、grep 不再精确命中），产物重建后自检恢复通过。**写文档提及占位符时一律用零宽空格断开或改述**；
3. **产物内 `sizeKB`/体积口径**：沿用 M2 评审结论——体积以文件实际字节为准（本轮 viewer 自身增量 +9.9KiB ≈ 模板增量；产物较上一提交 +21.4KiB，其中约 11.5KiB 为 head 胶囊与提交面板的数据追赶，与 M1/M2 的「陈旧生成物补齐」同型）；
4. **幂等验证**：同状态连续两次重建字节一致（`cmp` 通过）。

## 核验方式（Linux + Firefox headless）

- M1 基线的「外壳页 + 固定宽 iframe」为 Windows Edge 钳制方案；Linux Firefox `--window-size` 精确生效（375×812 实测输出 375px 宽图），直接截图即可；
- localStorage 在 Firefox headless 各次调用间不保证落盘 → 截图主题态用**变体文件**（`sed` 注入 `<html data-theme="light">`；boot 脚本已设计为「属性已存在则跳过存储读取」，变体注入即权威）；
- 动效（目录淡入 `--t-med`）会与截图时机竞争 → 截图变体统一注入 `<style>*{transition:none!important}</style>`；
- 溢出审计：变体内嵌脚本读取 `html/#main/body` 的 `scrollWidth-clientWidth` 画进角标，1920/1440/900/375 × 双主题全部 0px；
- 打印预览：Firefox headless 不支持 `--print-to-pdf`，采用「`@media print{` → `@media print,screen{`」变体在屏幕上呈现同一套打印规则（分页断点不可见，其余与真实打印一致）；
- 主题切换链路（按钮 → `applyTheme` → 属性/存储/图标）以注入 `themebtn.click()` 的变体实测：`afterClick=light` 全页变浅 ✓；localStorage 记忆以真实 profile 复核：后续会话首帧即浅色 ✓。
