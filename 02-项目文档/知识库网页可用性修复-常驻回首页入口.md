# 知识库网页可用性修复（常驻回首页入口）

> 记录 `kb-viewer-template.html` 常驻回首页入口改造（KNOWLEDGE-47）的实现要点与核验方式，承接 [知识库网页功能增强（M3 实现）](知识库网页功能增强-M3实现.md)。改动动机：进入文档并向下滚动后，界面无任何常驻回首页途径——唯一入口是文档页顶部面包屑里 0.8rem 的「首页」小字，滚离页首即不可见；顶栏 logo 与侧栏均无首页入口。

## 结论（改了什么）

仅改 `kb-viewer-template.html`（净增约 35 行）并重建 `知识库.html`：

1. **顶栏 logo 变为可点击**：`onclick="goHome()"` + `cursor:pointer` + hover 变色（`--accent2`）+ `title="回到首页"`。顶栏本身 fixed 常驻，文档页滚动到任意位置都可一键回首页；
2. **侧栏顶部新增常驻「首页」项**：`buildNav()` 在渲染所有分区之前插入（nav 第一个元素），home 单色描边 SVG（`UI_ICON.home`，M2 图标体系同款）+「首页」文本；点击经 `goHome()` 回首页；浏览首页时呈 `.active` 高亮（accent 左竖条，与文档项同一视觉语言）；搜索过滤下仍保持可见；
3. **统一回首页动作 `goHome()`**：logo 与首页项共用——搜索态先清检索（复用 `onSearchInput()` 现有链路）→ 复位 `location.hash=''` → 窄屏（<900px）顺带收侧栏抽屉；
4. **配套一行**：`renderWelcome()` 进入首页时把 `#main` 滚动复位到顶（与 `renderDoc()` 同款兜底）。此前从深滚动位置的文档回首页会落在首页半截处（面包屑「首页」路径同样存在），不修则新入口的「回首页」落点违和。

## 关键实现要点

### 为什么不是裸 `location.hash=''`（方案确认稿原文）

`hashchange` 监听器有一道搜索门禁 `if(state.searchQ) return;`：检索结果页里裸改 hash 会被门禁直接吞掉，点 logo/首页项毫无反应（首屏感受是「点了没动静」）。`goHome()` 先清检索再复位 hash，让回首页在**文档页 / 首页 / 搜索结果页**三种视图下都成立；清检索走 `onSearchInput()` 的空串分支，自动触发 `buildNav('')` 重建侧栏与 `renderWelcome()`，零新增渲染逻辑。

### 首页项 active 态的判定

`setActiveNav()` 追加：`!state.current && !state.searchQ` 时给 `#nav-home` 加 `.active`。两个条件缺一不可——搜索结果页的 `state.current` 也是 `null`，缺 `searchQ` 条件就会误亮。`buildNav()` 每次搜索都整体重建侧栏，active 态必须放在 `setActiveNav()` 里统一维护（与文档项同机制），不能在渲染时写死。

### 样式与位置复用

- 首页项置于 `nav.appendChild` 序列最前；「最近提交」面板仍在末尾（仅非搜索态追加），互不影响。检索结果页也能一键退出，正是「常驻出口」的价值之一；
- 样式全走既有令牌（`--bg-hover` / `--nav-active` / `--accent`），图标 chip 复用分区头 `.ico` 的 26×26 规格，不新增任何色值，浅色主题自动适配；
- 窄屏抽屉零额外代码：首页项就在 `#sidebar` 内随抽屉开合，点击后的收抽屉由 `goHome()` 兜底（与 `.nav-item` 点击行为一致）。

## 坑（本轮新增，后来者必读）

1. **`#main` 带 `scroll-behavior:smooth`**：脚本里 `scrollTop = 3000` 是异步动画，赋值后同步读取拿到的还是旧值——自动化断言要么改用 `scrollTo({behavior:'instant'})`，要么留出动画时间再读（本轮测试连踩两次）；
2. **snap 版 Firefox 拉起自动化**：snap 无法读 `/tmp` 下的临时 profile（报 `Could not find profile folder`），puppeteer 的 launch 路径不可用；须用 `-profile <普通目录>` 手动拉起 + `--remote-debugging-port`，再 `puppeteer.connect({browserWSEndpoint, protocol:'webDriverBiDi'})` 接管。新版 Firefox 的 BiDi 只开 WebSocket，`/json/version` HTTP 发现端点已不存在，`browserURL` 探测同样不可用；
3. **占位符坑沿用 M3 结论**：模板注释与文档正文都不得出现占位符字面量，本文一律以改述规避。

## 核验方式

- **重建幂等**：`python kb_build_viewer.py` 连续两次重建 `cmp` 字节级一致；head 胶囊仍取 kb-commits.json 的 `_meta.content_head`（本轮为 bcb08cbc），产物 7503 KB（模板增量 ≈ +2.3 KB）；
- **自动化用例（30 项断言全过、无页面 JS 错误）**：puppeteer-core 经 WebDriver BiDi 驱动 Firefox 158 headless，覆盖：首页项存在/置顶/active、logo 光标与 title、文档页滚动 3000px 后点 logo 与侧栏项均回首页且主区回顶、active 高亮切换、搜索态（结果面板、首页项可见不误亮、点击清搜索并回首页）、Ctrl+K 聚焦、Esc 清空、亮/暗主题切换、窄屏 375×812 抽屉内首页项可见可用且回首页后抽屉自动收起；
- **截图核验**：暗色首页 / 亮色首页 / 窄屏抽屉三张，首页项置顶高亮、双主题均适配、布局无溢出。

## 待办与门禁

- **上游问题（本轮发现，不在 KNOWLEDGE-47 授权范围，未动）**：检索结果页点击结果卡片不生效——`hashchange` 门禁 `if(state.searchQ) return;` 会把卡片 onclick 写入的 hash 变更直接吞掉（即上文裸 `location.hash=''` 失效的同一根因）。如需修复（门禁放行 `docByHash(h)` 命中的文档，或卡片点击改调 `renderDoc`），待成员决策后另行开工；
- 面包屑「首页」小字保留不动（文档页头的一部分，与两个常驻入口互为补充）。
