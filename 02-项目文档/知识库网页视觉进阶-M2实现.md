# 知识库网页视觉进阶（M2 实现）

> 记录 `kb-viewer-template.html` M2 视觉进阶（首页改版 + SVG 图标体系 + 代码语法高亮）的实现要点与关键取值，承接 [知识库网页视觉设计规范（M1 基线）](知识库网页视觉设计规范-M1基线.md)。完整改动以模板文件为准，本文记录「为什么这么做」与「坑」。

## 结论（M2 改了什么）

- **首页改版**：欢迎页重构为 hero 区（徽章胶囊 + 渐变主标题 + 副标题 + 仓库/分支/同步/HEAD 元信息胶囊）+ 四张统计卡（知识分类 / 文档总数 / 总字数 / 内嵌图示，全部从 `__KB_DATA__` 运行时计算）+ 分类卡片网格（SVG 图标 / 篇数徽章 / 简介 / mono 路径）；
- **图标体系**：侧栏分区与分类卡的 emoji 全部替换为内联 SVG 线性图标（单色描边、`stroke:currentColor` 继承分区色），顶栏搜索图标一并 SVG 化；导航与欢迎页零 emoji 残留；
- **语法高亮**：`pre>code` 增加零依赖轻量分词着色（C/JS/Python/Sh/JSON + 通用回退），marked 现有渲染（表格/引用/内联代码胶囊/图片）无回归。

## 关键实现要点

### 1. 首页（视觉语言参考 index.html，令牌复用 M1）

- 新增唯一派生令牌 `--grad:linear-gradient(135deg,#4f8cff,#9b6ce0)`（主色 `--accent` + 分区紫 proto `#9b6ce0`），用于 hero 渐变字、统计卡数字与顶线；其余配色/圆角/过渡全部复用 M1 的 `--bg/--bg2/--border/--t-fast/--t-med`，未另起变量体系；
- 统计卡数据运行时计算：总字数 = 各文档 `stripFrontMatter(content).body.length` 求和（≥1 万显示「x.x万」）；内嵌图示 = `Object.keys(KB.images).length`；同步信息移到 hero 元信息胶囊（修复参考稿「统计卡 4+1 排布不齐」的问题）；
- 分类卡片注入每卡 CSS 变量 `--sc`（分区色）、`--sc-soft`（色值+`21` 透明后缀 ≈13%）、`--sc-line`（+`59` ≈35%），与侧栏 M1 的 `--sec-a12` 手法一致，不依赖 `color-mix()` 以兼容旧内核。

### 2. SVG 图标体系（不改 kb-*.py 的覆盖式渲染）

- emoji 定义在 `kb_build_viewer.py` 的 `SECTIONS` 元数据里（禁改脚本），故在模板 JS 建立「分区 id → 内联 SVG」映射 `SEC_ICON`，`secIcon(sec)` 渲染时覆盖，**未登记 id 的分区回退原 emoji**（未来脚本新增分区不会坏）；
- 图标为 feather 风格 24×24 描边路径，全局基类 `.ico-svg{fill:none;stroke:currentColor;...}`，颜色由容器的 `color`（分区色）继承；侧栏图标底色改由 `--sec-a12` 提供（JS 不再内联 background）；
- 映射：esp→cpu 芯片、imu→罗盘、stm32→扳手、qt→显示器、linux→终端、proto→文档卷、kb→书本。

### 3. 语法高亮（零依赖，模板净增仅 ~4KB）

- **选型**：压缩 highlight.js + 主题约 30–50KB；自写分词器约 4KB 且无主题适配损耗。覆盖库内实际使用的语言（统计：c/cpp 39、json 28、bash 17、python 4、javascript 2），其余语言走通用规则（块/行注释、字符串、数字），`text/tex/mermaid/markdown/diff` 等纯文本类**直接原样转义输出**（避免把 `#` 标题当注释之类的错误着色）；
- **实现**：每语言一张「捕获组正则表」（块注释→行注释→字符串→数字→标识符按优先级排列），匹配后按组号定 token 类型；标识符再查关键字表，后跟 `(` 判定为函数调用；Python 三引号串与 C 预处理器行（`^[ \t]*#…`，m 标锚定行首）、Sh 变量 `$$…` 各有专属规则；未闭合注释/字符串有兜底分支，不会吞全文；
- **主题**（单一深色，由 M1 令牌派生）：`.tk-k`=accent2 `#7aa5ff`、`.tk-n`=orange、`.tk-c`=fg-faint 斜体、`.tk-p`=accent、`.tk-s`=#62c48f（`--green` 深底提亮）、`.tk-f`=#b48ce0（分区紫同族）；
- **坑**：转义统一在 `hlHighlight` 内完成（`renderer.code` 不再自行 esc）；复制按钮读 `code.textContent`，span 不影响复制；搜索高亮本就跳过 `pre/code`，无冲突。

## 体积与构建

- 模板净增 **12.9KB**（CSS ~5KB + SVG/图标映射 ~2KB + 高亮器 ~4KB + 首页渲染改写 ~2KB），远低于 60KB 预算；
- 重建按 M1 方式（`kb-sync.build_once()` 同序调用，`kb_build_viewer.py` 直跑仍会 `KeyError: 0`，见 M1 基线文档）；本次重建另含陈旧生成物的数据追赶 +34KB（commit 3034d2f 新增的 IMU/506 文档，文档 56→59），**viewer 自身增量以模板 12.9KB 为准**；
- 幂等验证：同状态连续两次重建字节一致（`cmp` 通过）。

## 核验方式（Windows）

- 沿用 M1 基线的 Edge headless 截图方案；<500px 宽度用「外壳页 + 固定宽 iframe」；本次加做**溢出审计页**：外壳页读取 iframe 内 `html/#main` 的 `scrollWidth-clientWidth`，把结果（PASS/FAIL+像素值）画进截图角标，1920/1440/900/375 四档全部 0px 溢出；
- marked 回归核验点：表格（AT 指令集）、引用块、内联代码胶囊、base64 内嵌图片（IMU流程.md 坐标系图 3 张）均正常；源文档里本身的空 ```json 围栏会渲染空代码块，属内容原貌非渲染回归。
