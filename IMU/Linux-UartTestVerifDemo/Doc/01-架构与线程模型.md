# 01 架构与线程模型

> 源码：[Code/main.c](../Code/main.c)、[Code/drv_serial.c](../Code/drv_serial.c)、[Code/bsp_uart_queue.c](../Code/bsp_uart_queue.c)、[Code/bsp_uart_protocol.c](../Code/bsp_uart_protocol.c)

## 三层架构

参照 `feature/LinuxCanTestVerifDemo`（CAN 分支）分层，换平台只换驱动层：

```text
main(入口分发+统计显示) ── bsp_uart_protocol(帧同步/CRC/统计/解析)
     │       │                  │
     │       └─ bsp_at_test / bsp_hex_test(指令与协议验证)
     │                          │
bsp_uart_queue(字节流SPSC环形队列)
     │                          │
drv_serial(termios串口驱动)
```

| 层 | 模块 | 职责 | 依赖 |
|----|------|------|------|
| 驱动层 | drv_serial | 仅封装系统调用（open/read/write/termios），不含任何协议逻辑 | 无 |
| 队列层 | bsp_uart_queue | 字节流缓冲，解耦接收与解析节奏 | 无 |
| 协议层 | bsp_uart_protocol | 帧同步、CRC16 校验、帧级统计、数据包解析 | 无（纯函数+内部静态状态） |
| 应用层 | main / bsp_at_test / bsp_hex_test | 功能分发、线程管理、显示；AT/HEX 验证器自管串口事务 | 驱动层（+协议层 CRC 算法思想） |

## 线程模型（功能1 数据流统计）

```text
UartRecvThread(生产者)  --字节流-->  UartQueue  --字节流-->  UartParseThread(消费者)
   阻塞read()        BspUartQueuePush()         BspUartQueuePop()   帧同步/CRC/统计/解析
                                                                     │
                                       主线程: 每秒 BspUartProtocolPrintStat() 刷新显示
```

- **接收线程**：`DrvSerialRecv` 阻塞读 → `QueuePushBytes` 逐字节入队；维护 `G_LastRxSec`（最近收字节时刻）与 `G_RxBytes` 累计
- **解析线程**：逐字节 `BspUartProtocolOnByte` 喂状态机（内部完成 CRC 校验/统计/解析）
- **主线程**：每秒打印统计表；终端模式利用固定 31 行布局原地回退刷新，管道模式退化为 5 秒全量打印

### 设计要点

1. **SPSC 无锁**：单生产者单消费者，各持一个下标，`volatile` 保证可见性，无锁无阻塞（详见 [03](03-环形队列模块-bsp_uart_queue.md)）
2. **优雅退出**：SIGINT/SIGTERM 信号处理只置 `G_Running=0`（异步安全），驱动层 `read` 的 `EINTR` 自旋重试保证信号能打断阻塞读；退出时打印最终汇总（接收字节数/CRC 通过帧数/队列丢弃字节/各包统计）
3. **单调钟计时**：所有时刻取 `CLOCK_MONOTONIC`，不受系统时间跳变影响；平均 Hz = (帧数−1) ÷ (末帧−首帧时刻)
4. **只统计 CRC 通过帧**：坏帧、非法长度帧自动剔除并可恢复同步，帧间夹垃圾字节不受影响

## 功能分发（单程序三功能）

`./imu_test [串口设备] [波特率] [功能] [功能参数]`

| 功能 | 第3参数 | 功能参数 | 走向 |
|------|--------|---------|------|
| 1 数据流统计（默认） | 非 2/3，视为秒数 | 秒数，0=直到 Ctrl-C | `RunStatMode`：起双线程+主循环打印 |
| 2 AT 指令验证 | `2` | 0=仅安全组（默认），1=+风险组 | `BspAtTestRun`（自管串口事务） |
| 3 HEX 协议验证 | `3` | 0=仅安全组，1=+风险/异常组，2=压力模式 | `BspHexTestRun`（自管串口事务） |

功能 2/3 为"事务式"验证（发一帧→等应答），不走路由队列，直接在验证器内部完成收发与混流容错；功能 1 为"流水线式"持续接收，走双线程+队列。
