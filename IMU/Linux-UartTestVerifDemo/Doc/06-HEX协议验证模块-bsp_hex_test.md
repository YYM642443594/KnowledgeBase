# 06 HEX 协议验证模块 bsp_hex_test

> 源码：[Code/bsp_hex_test.c](../Code/bsp_hex_test.c) / [Code/bsp_hex_test.h](../Code/bsp_hex_test.h)
> 依据：源工程《用户协议》第 3.2 章串口交互协议；固件行为权威 = 固件工程 `bsp_parse.c`（2026-10-21 逐 ID 核对）

## 定位

HEX 交互协议逐报文验证器：19 个报文 ID 常量（对应固件 `RECV_ID_xxx_E`）全覆盖，用例表驱动 + 帧级收发 + 混流容错。入口 `BspHexTestRun(pDev, Baud, Mode)`：Mode 0=仅安全组 / 1=+风险+异常组（32 条）/ 2=压力暴力模式。

## 帧格式（与推送协议的差异）

```text
请求帧: AA 55 | CMD(ID高字节) | ID | Op | Len(2,小端,整帧长) | DATA | CRC16(2,小端)
应答帧: AA 55 | CMD | ID | Len(2) | DATA | CRC16      ← 无 Op 字段
```

- Op：`0x00` 查询 / `0x01` 写 RAM（即时生效，掉电丢）/ `0x02` 写 FLASH（掉电保存）
- CRC16 与协议层同算法（初值 0x3692、多项式 0x8408 反向），此处独立实现保持工具自包含
- 帧字段命名访问宏 `HEX_FR_CMD/ID/LEN`、`HEX_RESP_DATA/DATALEN/DATA0`、`HEX_REQ_DATA`，代码零魔法下标

## 用例分组（32 条 + 压力模式）

| 组别 | 内容 | 判定 | 还原策略 |
|------|------|------|---------|
| 安全组 | 13 个 ID 查询（0x0003版本/0x0004频率/0x0006算法模式/0x0007推送状态/0x0012PPS/0x0015坐标系/0x0016串口波特率/0x0017CAN波特率/0x0018SN/0x0022量程×2/0x0101A值/0x0103电量）+ 0x0021 YAW 归零（写 RAM 掉电不保存） | 应答 CRC 过后按文档校验：数据域长度、**值域白名单**（频率档 0x01~0x09、坐标系 24 值表、波特率 7 值表、CAN 3 值表、SN 16 字节可打印、量程档位表），并提取关键值 | 查询结果**同步缓存**（频率档/算法模式/推送状态/PPS/坐标系），供风险组构造设置值与还原帧 |
| 风险组 | 写 RAM：0x0004 频率、0x0006 算法模式、0x0007 推送开关、0x0011 报文推送开关、0x0012 PPS、0x0015 坐标系、0x0020 零偏、0x0019 时间同步 | 应答 `DATA[0]==0x00` 即过 | **动态成对还原**：设置值避让原值（原 10Hz 则设 20Hz），过完立即用查询缓存构造还原帧下发（不计分）；0x0019 直接同步主机时间 |
| 异常组 | ① 静默无应答 5 条：CRC 错帧/非法操作符/未知 ID 0x0023/Len 超限/0x0008 磁力计校准（**固件 0x00 分发表未实现**，真机实测静默）；② 无效应答 1 条：频率非法操作符 0x03（固件末尾无条件应答 DATA[0]=0）；③ **ABN_WQ 非法值写入→行为查询** 3 条：频率非法档 0x0A 回落档5（50Hz）/坐标系 837 直写无校验/PPS 非法模式 5 归零 | 无应答类超时即 PASS；写查两步类先验写入应答再查询确认固件行为 | ABN_WQ 无条件还原（外层统一执行） |
| 有意排除 | 0x0005 蓝牙名称写入（掉电保存无法还原）、0x0016/0x0017 波特率写入（FLASH-only 断链）、0x0022 量程写入（FLASH-only）、各 ID FLASH 档（Op=0x02） | — | 掉电保存/断链类不进自动流程 |

## 混流容错

- **滑窗取帧**：接收缓冲滑窗搜帧头 → CMD/ID 匹配 → CRC 校验，推送报文（如 0x0001）与坏帧自动剔除
- **同 ID 混叠过滤**：0x0022 量程与数据包4推送同 ID，按期望应答帧长（18 字节）过滤推送帧混叠
- **事务前清理**：每次事务前 `tcflush` 清串口残留
- 查询缓存无效时风险项自动 SKIP（避免无法还原）

## 0x0022 量程查询：文档≠固件的典型案例（V1.6.1~V1.6.4 定因过程）

1. 文档 3.2.3.17 只给设置发送表 → 按设置帧同构构造查询帧真机无应答
2. 改**多格式自动探测**：类型+预留8（CAN 0x115 查询映射）→ 类型1 → 设置帧同构，命中即标注 `[查询格式:xx]`
3. 仍无应答 → **宽容收包**兜底（不限应答长度、跳过推送帧），档位白名单通过即标注 `[宽容:应答Len=n]`，失败打印原始帧 hex
4. 查固件源码定因：查询分支只认 `DATA[0]` 类型字节不校验长度（3 格式均可达），但**应答 PayLoad=16/整帧 24 字节**与文档回复表（10/18）不符——此前按 18 过滤把固件 24 字节应答吞掉造成假超时
5. 终局：固件改回 PayLoad=10 对齐文档；工具 18 直接命中 + 保留 24 宽容兜底兼容旧固件

**方法论沉淀**：文档缺失/不一致以固件为权威；期望帧长过滤要给"宽容模式"留后门，超时诊断要打印原始帧。

## 其他固件对照要点（逐 ID 核实）

- 0x0014 复位仅 RAM 档（Op=0x01）应答并复位，固定放用例表末
- 0x0018 SN 应答按 `SN[15]→SN[0]` 倒序填充，工具原样显示
- 0x0004 查询按文档补 DATA 字节（查询时填 0）；0x0006 固件实际支持模式 1~5（文档仅列 4 种）
- 固件 0xAA55 状态机（`HexCmdParse`）**无帧接收超时**：截断帧后按声明 Len 持续等字节、吞掉后续合法帧内容（错位 2 字节需多次查询恢复）——固件可改进项（建议加帧间超时重置）

## 压力/暴力模式（功能3 第4参数=2）

| 项 | 内容 | 实测结果 |
|----|------|---------|
| 无效应答静默 | CRC 末字节翻转 + 未知 CMD 0x09 | 预期无应答 |
| 高频连发 | 200 帧不等应答连发 | 固件收 2 帧其余丢弃，不卡死 |
| 垃圾前缀重同步 | 随机 1~16 字节 + 合法版本查询 ×50 轮 | 50/50 恢复 |
| 截断帧恢复 | 帧只发一半（轮换停在 Len/CRC 域前）×10 轮 | 10/10 恢复 |
| fuzz 随机帧轰炸 | 固定种子 0x3692 可复现，1000 帧 50% 伪造 AA55 | 轰炸后探活存活 |

安全设计：压力帧全程无持久副作用（CRC 错/未知 CMD 均被固件静默丢弃）；每项结束版本查询探活（3 次重试），失败自动发复位帧兜底重启再探活。

> 真机回归：模式 2 5/5 PASS；模式 1 全量 32/32 PASS（含 3 条 ABN_WQ 还原一致）；pty 冒烟多场景 PASS。
