# 07 主入口与构建运行（main.c / run.sh）

> 源码：[Code/main.c](../Code/main.c)、[Code/run.sh](../Code/run.sh)

## main.c 职责（V1.7.8）

统一入口：参数解析 + 功能分发 + 功能1 的线程管理与统计显示。当前版本 `G_Version = "V1.7.8"`。

### 全局对象

| 对象 | 用途 |
|------|------|
| `G_Serial`（DrvSerial_S） | 串口控制块，默认 `/dev/ttyUSB0 @921600` |
| `G_Queue`（UartQueue_S） | 字节流 SPSC 队列 |
| `G_Running`（sig_atomic_t） | 运行标志，SIGINT/SIGTERM 置 0，线程据此退出 |
| `G_StartSec / G_LastRxSec / G_RxBytes / G_FrameOk` | 统计时长/最近收字节时刻/累计字节/累计 CRC 通过帧 |

### 关键函数拆分（≤30 行规范）

| 函数 | 职责 |
|------|------|
| `ParseSerialArgs` | 位置参数解析：设备/波特率/功能/功能参数 |
| `DispatchFeature` | 分发：第3参数 2→`BspAtTestRun`，3→`BspHexTestRun`，其余→功能1 并按秒数处理（兼容旧 uart_stat 用法） |
| `StatInit / StatStartThreads / StatRunLoop / StatFinish` | 功能1：串口+队列初始化、双线程启动、周期打印主循环、收尾汇总 |
| `RecvOneRound / QueuePushBytes` | 接收线程单轮：阻塞读→入队，维护 RxBytes/LastRxSec |
| `StatPrintOneMsg / StatPrintIntervals / StatPrintTsDelta / StatPrintSummary` | 统计显示：单包行/间隔行/Δt行/收尾汇总 |
| `StatMaybePrint` | 节流打印：终端 1 秒原地刷新（回退 31 行覆盖重绘），管道 5 秒全量 |

### 参数与用法

`./imu_test [串口设备] [波特率] [功能] [功能参数]`

| 功能 | 参数 | 功能参数 | 示例 |
|------|------|---------|------|
| 1 数据流统计（默认） | 非 2/3 视为秒数 | 0=直到 Ctrl-C | `./imu_test /dev/ttyUSB0 921600 10` |
| 2 AT 指令验证 | `2` | 0=仅安全组（默认），1=+风险组 | `./imu_test /dev/ttyUSB0 921600 2 1` |
| 3 HEX 协议验证 | `3` | 0=仅安全组，1=+风险/异常组，2=压力模式 | `./imu_test /dev/ttyUSB0 921600 3 0` |

## run.sh 一键脚本流程

```text
帮助(-h) → 参数缺省填充 → gcc 编译单目标 imu_test(-O2 -Wall, -lpthread)
→ 串口存在性检查(不存在则列出 /dev/ttyUSB* /dev/ttyACM*)
→ 占用检查(lsof, 警告互抢串口) → 交互菜单(1统计/2AT/3HEX, 回车默认)
→ 模式子菜单(2: 0/1; 3: 0/1/2) → exec imu_test 对应参数
```

构建命令（手动等价）：

```bash
gcc -O2 -Wall -o imu_test main.c drv_serial.c bsp_uart_queue.c \
    bsp_uart_protocol.c bsp_at_test.c bsp_hex_test.c -lpthread
```

## 排障经验（真机踩坑沉淀）

1. **统计/解析停滞、CRC 失败帧暴涨** → 先查串口抢占：`lsof /dev/ttyUSB0`。曾因 30 分钟长跑的旧实例未退出，新实例 11s 仅收 2 帧、411 帧 CRC 失败——**两实例同读会瓜分字节流，任何单实例都组不出完整帧**（V1.1.1 定性）
2. **"最新帧解析"数值不动** → 正常每秒都在变（时间戳走秒）；若完全冻结优先怀疑串口被抢占而非解析逻辑（本工具每帧无条件更新）
3. **队列丢弃字节 > 0** → 解析线程消费不及，正常应为 0
4. **CRC 通过帧数 ≈ 接收字节数 ÷ 平均帧长** → 链路无误码的经验判据
