# 参数页升级 SN 乱码与预留区扩展机制报告（2026-10-23）

> 涉及版本：V3.0.0.14/15 → V3.0.0.21+ 升级链路；A/B 双页参数区（bsp_data_interaction.c）
> 关联工程：IMU_303_351 / IMU_103_303_333（共用 BSP_IMU.git 子仓库）

## 一、问题现象

设备从 V3.0.0.14/V3.0.0.15 升级到 V3.0.0.21+ 后，AT+SN 查询与上报的 SN 显示为乱码
（如 `53IP?+Z351`），且乱码会被固化（重启不恢复）。

## 二、根因分析

### 2.1 参数页格式演进链（真机验证）

| 版本 | 页数据长度 | 差异 |
|------|-----------|------|
| L1: V3.0.0.14/15 | 96B | 无量程字段（AccScale/GyroScale） |
| L2: V3.0.0.16~19 | 100B | 含量程；无 UserCanSimpDataPushCfg/0x0022 位 |
| L3: V3.0.0.20~21 | 104B | 无 Reserved 预留区 |
| 当前 | 204B（预留区启用后仍 204B） | 头 12B{Magic,Sequence,Crc}+数据 |

### 2.2 乱码产生链路

旧固件页（96B，带历史 CRC）在新固件下按 `sizeof(ProductInfo_S)` 复验 CRC 必然失败
→ A/B 双页全部判无效 → 走"裸迁移"兜底路径 → 兜底路径把 **wrapper 页头 12 字节读进
数据区**（偏移错位），SN 字段落进 Magic 小端字节 `35 49 50 33` = "5IP3" 系字符
→ 乱码被上电初始化流程固化写入。

**教训：页头包装结构一旦引入，任何"读长度=sizeof(结构体)"的路径都必须显式处理
历史长度差异，兜底迁移不能假设数据区从 0 偏移开始。**

## 三、修复方案

### 3.1 四级长度复验 + 按格式迁移

`BspProductInfoPageCheck()` 按顺序复验 CRC：当前 sizeof(204) → L3(104) → L2(100) → L1(96)，
返回 1/2/3/4 标记格式；`BspProductInfoLoadFromFlash()` 按格式分别迁移：

- **L3**：前缀与当前布局完全一致，直接拷 104B，Reserved 清零
- **L2**：拷 100B + 旧位域重映射（插入 0x0022 位后 PPSStatus/PPSMode/ZeroBias 整体后移 1 位）
  + UartxEnable[0]=1
- **L1**：拷位域区之前前缀 + 位域搬运至当前偏移后重映射 + ConfigInitFlag 单独搬运

### 3.2 历史长度必须相对推导，不可绝对硬编码

本工程按**短枚举 ABI** 编译（枚举容器取可容纳所有枚举值的最小类型）：
`DataPushFre_E` 实际 2B、`ArithmeticMode_E` 实际 1B，而非直觉的 4B。
按 4B 枚举手推的旧 sizeof（如 124）与真机不符（实际 96），导致 L2 修复反复失败。

```c
/* 一律由当前布局相对推导 */
#define PRODUCT_INFO_LEGACY2_DATA_SIZE   (offsetof(ProductInfo_S, UserCanSimpDataPushCfg))
#define PRODUCT_INFO_LEGACY_BITS_OFFSET  (offsetof(ProductInfo_S, ConfigInitFlag) - 2U)
#define PRODUCT_INFO_LEGACY1_BITS_OFFSET (PRODUCT_INFO_LEGACY_BITS_OFFSET - 4U)
/* L3 例外:必须用历史定值,见 3.3 */
#define PRODUCT_INFO_LEGACY3_DATA_SIZE   104U
```

### 3.3 L3 移动锚点陷阱

L3=104 原本等于 `offsetof(Reserved)`，但**预留区启用新字段后该偏移会后移**，
锚定它会令 L3 校验长度漂移失效。凡"历史版本的定长"必须固化字面常量
（由该版本二进制决定，永不随当前布局变化）。

### 3.4 预留字段扩展机制（根治未来加字段的升级兼容）

`ProductInfo_S` 末尾启用 100B（后因 303/333 RAM 缩至 94B）Reserved 区，规程固化在头文件注释：

- 新增字段 = 在注释与 Reserved 之间声明 + Reserved 减对应字节数 + 维护分配表
- 新字段默认值必须为 0 语义（旧页该位置恒为 0，迁移后即合法默认值）
- 多字节字段放 4 对齐偏移；禁止改动现有字段顺序/类型、禁止在预留区前插入字段
- **效果：布局与 CRC 长度恒定，后续加字段无需再做格式迁移**

已启用字段：`PPSSwitchType`（PPS 开关来源，100→99）、PPS 三通道配置组等。

### 3.5 读取路径 RAM 优化（303/333 约束）

303/333 为 20KB RAM，双 216B 暂存 + 900B 预留曾使余量压至 104B。
改为**单缓冲串行复用**（读 A 校验→读 B 覆盖→胜者为 A 时重读 A）+ Reserved 缩至 94B，
余量恢复至 ~3.5KB。单主循环上下文调用无并发，Flush 构造阶段改读 8B 页头取活跃页序号。

## 四、验证结论

- 351 测试设备（V3.0.0.15→21+ 升级链）dump 显示 PageA `crc=OK(legacy)`、SN 完整保留
- 旧页升级后 SN 不再丢失；已损坏设备需一次性重写 SN
- 303/333 拉取同版 bsp 后编译通过，RAM 余量 ~3.5KB

## 五、经验教训汇总

| # | 教训 |
|---|------|
| 1 | 带页头包装的 Flash 参数区，兜底迁移路径最容易成为升级事故源，必须按历史格式长度显式复验 |
| 2 | sizeof 推算必须以目标编译器真实 ABI 为准（短枚举容器按最小可容纳类型），以真机 dump 输出为最终证据 |
| 3 | 历史定长用字面常量固化，禁止锚定会随布局漂移的 offsetof |
| 4 | 预留区机制 + "新字段默认 0 语义"规程，是结构体演进与旧页兼容的最小成本组合 |
| 5 | RAM 紧张的工程（20KB 级）做双页备份时优先考虑串行复用单缓冲 |
| 6 | 离线手工转录 hex 复算 CRC 与存储值不符时，优先怀疑转录笔误而非算法差异，用设备端原位计算交叉验证（本例即为转录笔误，算法自始正确） |
| 7 | 921600 波特率随机丢应答，设备端无 ORE/复位痕迹时优先排查 USB 转串口链路（详见 303_333 工程同名报告） |
