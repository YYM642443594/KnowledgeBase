# 506 工程 GD32F303CB 升级 CGT6 芯片迁移报告

> 工程：GD32F303MCU（分支 `feature/506Custom`），Keil MDK + GD32F30x 器件包
> 器件变更：GD32F303CBT6（HD 系列，128KB Flash / 32KB RAM）→ GD32F303CGT6（XD 系列，1MB Flash / 96KB RAM）
> 关联提交：e5ef004

## 一、现象

在 Keil 中把目标器件从 GD32F303CB 切换为 GD32F303CGT6 后全量编译，出现 **1320 个编译错误**，集中在 gd32f30x.h 头文件。

## 二、根因

Keil 器件包按所选器件**自动注入 `GD32F30X_XD` 宏**（Device 设置不可见），而工程 C/C++ Define 里**残留手工添加的 `GD32F30X_HD`**：

- gd32f30x.h 对 HD / XD 使用**平行 `#ifdef` 分支**（非 `#if defined(A) || defined(B)` 互斥结构），两个宏同时定义时 IRQn 枚举、外设基址等被重复定义两份
- 结果：全套外设头文件连锁报"重复定义"，错误数上千，且首条错误指向的并不是真正的出错位置

## 三、解决方案

1. **C/C++ Define 清理**：删除手工的 `GD32F30X_HD`，仅保留器件包自动注入的 `GD32F30X_XD`（Define 栏里看不到的宏才是器件包给的，自己再加一遍就会双定义）
2. **启动文件替换**：`startup_gd32f30x_hd.s` → `startup_gd30x_xd.s`（中断向量表数量不同：XD 支持更多中断线），从工程移除旧启动文件、加入新文件
3. **IROM1 地址确认**：应用程序起始地址维持 `0x08006000`、大小 `0x1A000`（给 Bootloader/Loader 让出前 24KB）——CGT6 的 1MB 空间下此布局不变，应用上限可按需放宽

## 四、HD / XD 系列 Flash 特性核对（迁移避坑）

| 关注点 | 结论 |
|--------|------|
| 页大小 | HD 与 XD **前 128KB 均为 2KB/页**，扇区擦除逻辑无差异 |
| Flash 分配文件 | Loader / APP 的 Flash 分区配置（bsp_config.h 等）**无需修改** |
| 加固建议 | Loader 工程的 uvprojx IROM1 可收紧为 0x4000（24KB），防止误编入 APP 区（建议项，未强制） |

## 五、迁移后资源核算

- 器件资源：1MB Flash / 96KB RAM（CGT6），应用区可用约 1MB − 24KB(Loader) 
- 506 固件实测规模（修复后）：Code ≈ 97KB，RO-data ≈ 4.7KB，RW ≈ 0.4KB，ZI ≈ 25KB —— Flash 占用 <10%，RAM 占用约 26%，余量充足
- 全量编译 0 错 0 警

## 六、预防措施

1. 切换 GD32 器件型号后，**第一时间核对 Define 栏与器件包注入宏是否重复**（HD/CT/XD 等子系列宏互斥，只能存在一个）
2. 启动文件与子系列宏必须成对更换，单一更换必炸
3. 同系列不同容量型号（CB→CG）迁移重点是**宏与启动文件**，分区/页大小逻辑通常无需动；跨系列（F303→F407 等）则需全量评估
