# CAN 0x117地磁校准指令操作符错位修复报告

> 日期：2026-11-25　产品：506(全平台共用代码,修复随子仓同步至所有产品)　状态：已修复并提交(BSP_IMU `413356b`)

## 1. 现象

按协议向 CAN 0x117 发送地磁校准**关闭**指令 `01 00 00 00 00 00 00 00`(操作符=配置到RAM+开关状态=关闭),设备反而**开启**了磁力计校准,与协议不符。

## 2. 根因:字节序错位(把操作符当开关)

协议3.3.3.19定义0x117设置发送的8字节数据格式(《用户协议.md》L2059-2061):

| 字节1 | 字节2 | 字节3~8 |
| --- | --- | --- |
| 操作符(0x01=配置到RAM,0x00=查询,0x02=配置到Flash) | 开关状态(0x00=关闭,0x01=开启) | 预留 |

原实现(`BspCanMagCalibration_117`,bsp_parse.c)把**字节1(操作符)误当开关状态**解析:
`DataBuf[0]==0x01 → Set(1,3)开启;DataBuf[0]==0x00 → Set(0,0)关闭`。

按协议发关闭帧 `01 00 ...` 时,字节1=0x01 被读作"开启" → 校准被开启。单字节碰巧"能用"(全0帧`00 00...`可关闭)掩盖了错位,实测按协议发包才暴露。

## 3. 修复

按协议改双字节解析(bsp_parse.c `BspCanMagCalibration_117`):

| 发送数据 | 修复后行为 |
| --- | --- |
| `01 01 00...` | 开启地磁校准(进度帧经0x117回复,ReportMode=3) |
| `01 00 00...` | 关闭地磁校准 |
| `00 ...`(查询) | 0x117协议标注不支持查询 → 忽略不回复 |
| 操作符非0x01或开关非法 | 忽略不回复 |

ACK回复格式不变:同ID 0x117,字节1~4=float校准进度,字节5~8=0。

## 4. 影响面与兼容性

- **全平台生效**:该函数为共用代码、无宏隔离,303/333/351/506随子仓同步修复。协议层面0x117仅定义于唯一通用协议,无产品间冲突,属共性bug修正。
- **行为变化点**:旧格式全0帧`00 00...`(原实现碰巧可关闭)修复后按查询语义被忽略。**依赖旧错误格式的上位机/测试脚本须同步改为`01 00 00...`**。
- 同族指令排查:0x100~0x118其余CAN指令处理函数均为正确的"操作符[0]+值[1]"双字节模式(如0x114量程0x115滤波0x116等),仅0x117一处错位,无扩散问题。

## 5. 预防措施

1. **新写CAN指令处理函数时先对齐协议帧格式表**:逐字节核对"操作符/参数/预留"布局,禁止凭单字段直觉实现;
2. **带操作符的指令必须校验操作符合法性**:协议未支持查询的指令(如0x117)收到查询操作符应忽略,不得落入其它分支误动作;
3. **"碰巧能用"的帧格式不可作为回归基准**:全0帧关闭成功只说明旧实现未校验字节2,不代表协议正确;协议变更或新指令联调时以协议文档为准重验;
4. **协议双字段指令的测试须覆盖全组合**:开/关/查询/非法操作符四类帧各发一次并核对行为与回复。
