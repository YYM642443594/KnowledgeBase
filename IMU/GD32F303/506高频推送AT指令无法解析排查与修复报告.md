# 506高频推送AT指令无法解析排查与修复报告

> **状态（2026-11-24）**：本文第三节第 2、3 项修复（任务调度差值门控、RS485 周期窗口）**已按用户决策撤销回退**，当前代码仅保留第 1 项喂狗时间驱动修复（bsp_function.c +13/-3，Code=99096）。撤销后 1kHz 推送场景下"AT 指令无法解析"问题将回归（根因机制仍成立），本文根因分析与对照结论继续有效，供后续按需重启修复时参考。对照工程 IMU_303_351 无此问题的原因：①UART0 为 TTL 全双工（PA9/PA10 直连，无 DE 方向脚），发送期间照常接收；②发送为 TBE 中断+环形缓冲非阻塞（usart_driver.c），主循环不被整帧发送阻塞——均属硬件接口差异，非软件优势。

## 一、问题现象

- 0x0013 数据包按 1kHz（DataPushFre=1ms）推送时，主机发送 `AT+MSGID=13,0`、`AT+DATALINK=UART,0` 均无法被设备解析，推送无法停止（"关推送的指令插不进去"死锁）。
- 关联历史现象：开启 0x0013 推送数秒后自动关闭再开始，串口打印 `Reset cause: FWDGT timeout`（前期已单独修复，本文一并整理根因链）。
- 第一层修复（调度）烧录后现象依旧——提示存在第二层根因。

## 二、排查与根因（三层叠加）

### 根因1：整除调度相位锁死（喂狗饿死 / 解析饿死）

调度骨架 `BspAppLoopProcess` 用 `RunSysTicks % N == 0` 整除门控各任务。1kHz 推送时推送位于主循环末尾且为阻塞发送（0x0013 帧 ~115B@115200 ≈ 10ms），单圈墙钟时间稳定落在 [10,11)ms → 拍点快照恒 +10 推进 → 余数被锁死：

- **数学条件**：拍点步长 s 对 `%N` 锁死 ⟺ `s ≡ 0 (mod N)`。s=+10 恰好锁死 `%10`（解析）、间接锁死 `%5/%20/%100/%1000`；s=+2~+9 时余数周期性回到 0，不会锁死——锁死窗口极窄，需要"每圈必推（1ms 门控）+ 帧时×波特率恰好顶进 [10k,10k+1)ms"三条件共振。
- 后果链：`%1000` 喂狗不执行 → FWDGT 超时复位（已修）；`%10` 指令解析不执行 → RX 中断入队的 AT 字节无人消费（修喂狗后暴露）。
- RX 路径本身无问题：USART0 RXNE 中断逐字节入队 PC/HEX/AT 三个 512B 队列（源码 `bsp_parse.c`，位于上游 WorkRecord 仓库：`01.Code/GD32F3xxMCU/00.Code/BSP_IMU/00.Code/src/bsp_parse.c`），字节确实进队了。

### 根因2（现象主因）：RS485 半双工总线独占

UART0 对外为 RS485 半双工（PB1=DE 方向脚，源码 `hal_gd_uart.c` 位于上游 WorkRecord 仓库：`01.Code/GD32F3xxMCU/00.Code/01.HAL/src/hal_gd_uart.c`，发送前置高、TC 后拉低），**DE 拉高期间接收器物理禁用**：

```text
1kHz推送总线时间线: |←发送9.98ms(DE高,收不到任何字节)→|←0.3ms接收空隙→| 循环
AT+MSGID=13,0 = 15字节 ≈ 1.3ms@115200 > 0.3ms空隙 → 字节物理收不全
```

设备每圈只能收到指令的随机 2~3 字节碎片，AT 状态机永远凑不齐完整指令。推送关闭时 DE 常驻接收态，故 AT 正常——完美解释"只有高频推送时指令失效"。第一层调度修复后解析确实每圈在跑，但字节根本没进队列，现象依旧。

## 三、修复方案

### 1. 喂狗改时间驱动（bsp_function.c）

`RUN_FWDGT_FEED_MS 800U` 差值判断（FWDGT 超时 2000ms，留 60% 裕量）：差值判断对拍点步长不敏感，阻塞恢复即补喂。

### 2. 任务调度改时间驱动差值门控（bsp_function.c，506 宏隔离）

解析/200Hz姿态/10Hz磁校准/1Hz气压与状态/50Hz LabView 共 5 处 `%N==0` 改为 `(RunSysTicks - LastTick) >= N` 差值判断；非 506 工程走 `#else` 保留原整除分支，行为零变化。任务平均频率不变，无相位依赖（姿态链 dt 为 DWT 实测自适应设计）。

### 3. RS485 周期窗口（bsp_data_interaction.c，506 宏隔离）

`BspRs485TxAllowGet`：无状态时间模判定，每 `BSP_RS485_WIN_PERIOD_MS`(30ms) 留 `BSP_RS485_WIN_GAP_MS`(3ms) 总线空隙（占空 10%）：

```c
(NowTick % 30) < 27   /* 空隙期间跳过UART周期推送 */
```

- 空隙期各路 `LastPushTick` 不推进，空隙过后差值门控立即补发 → **长期平均推送率 = 配置频率**（3M 线速上限 ~2600 帧/s，补发无压力；仅每 30ms 一次 3ms 抖动）。
- AT 指令须完整落入空隙才可收全，单次成功率 ≈ (空隙−指令时长)/周期，**占空比决定响应灵敏度**：30ms/3ms 下 115200 指令（1.3ms）平均 ~0.5s 生效、3M 指令（0.05ms）~0.2s。参数教训：初版 254ms/4ms（占空 1.6%）单次成功率仅 ~1%，实测"指令响应不灵敏"（平均 ~26s）——长周期低占空窗口只保证"窗口存在"，不保证指令对准窗口；短周期高占空才能兼顾灵敏与平均频率。
- 覆盖主图/原始/HEX/AT 四路周期推送；CAN 两路不经 UART0 不受影响；PPS 模式 2 不加窗（脉冲推送场景无指令插入需求，与原行为一致）。
- 非 506 工程恒放行（`#else` 恒返回 1）。
- 未动 hal_gd_uart.c/h（约束：串口驱动不可改）。

### 4. 1kHz 可达的物理前提

帧率上限 = 波特率 ÷ 10 ÷ 帧长。0x0013（115B）@1kHz 需 1.15Mbps 线速：

| 波特率 | 0x0013 实际上限 | 1kHz 可达 |
|---|---|---|
| 115200 | ~100 帧/s | ✗ |
| 921600 | ~800 帧/s | ✗ |
| 2000000 | ✓ | ✓ |
| 3000000 | ✓（帧时 0.38ms，推荐） | ✓ |

506 波特率白名单已含 2M/3M 档，测试 1kHz 须先将设备与主机切至 ≥2M。

## 四、验证

- Keil 编译：0 错误，12 警告全部为既有基线；Code=99112（无状态窗口实现比定长窗口版还小 56B）。
- 非 506 工程编译隔离，二进制不含 506 逻辑。
- 上机验证要点：① ≥2M 波特率下开 0x0013@1kHz，统计帧率应为平均 ~1000 帧/s（每 30ms 一次 3ms 空隙，空隙后补发）；② 推送中发 `AT+MSGID=13,0`，平均 0.5s（115200）或 0.2s（3M）内生效，连续发送更快；③ 115200 下推送自动被线速钳在 ~100 帧/s。

## 五、行为影响（已知且无害）

1. 帧间隔偶发 +3ms（每 30ms 一次），帧不丢、帧内时戳字段连续。
2. AT 指令生效平均延迟：115200 下 ~0.5s、3M 下 ~0.2s（须完整落在空隙内，连续发送可显著加快）。
3. RunSysTicks 32 位回绕（~49.7 天）时窗口相位跳变一次，单个周期受影响，无实际影响。

## 六、预防措施

1. **整除调度纪律**：凡 `RunSysTicks % N == 0` 调度的任务，若同主循环存在可能阻塞 ≥1 拍的操作（串口阻塞发送等），一律改时间驱动差值门控。整除调度只在"圈耗时 ≪ 周期且稳定"时安全；锁死条件为拍点步长 ≡ 0 (mod N)。
2. **RS485 半双工推送设计**：DE 拉高期间接收器物理禁用，"连续推送 + 主机随时插指令"物理互斥，必须周期性留总线空隙；空隙期不推进推送节拍基准，靠差值门控补发保住平均频率。
3. **高频推送规格校验**：帧字节数 × 10bit × 频率 ≤ 波特率，1kHz@115B 帧最低 2M 波特率。
4. **排查方法论**："软件修复后现象依旧"= 还有第二根因，应及时下探物理层（半双工/方向脚/电平/接线），不要在同一抽象层反复找。本案调度修复修的是真 bug（解析饿死），但现象主因在 RS485 物理层。
5. 共用 BSP 文件产品差异宏隔离（沿用《506推送帧时间乱走排查与修复报告》纪律）；串口驱动 hal_gd_uart.c/h 不改动。
