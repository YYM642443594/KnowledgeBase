# 507 PPS 输入捕获功能接入报告

> 507 接入 PPS 秒脉冲输入功能，参照 GD32F1xx 工程 PA2/EXTI2 成熟方案。
> BSP_IMU 协议层（bsp_pps.c）全平台共用无需改动，缺口只在主工程硬件捕获层与时间同步消费点。

## 1. PPS 功能全景（软件层为全平台共用）

| 环节 | 位置 | 507 状态 |
|---|---|---|
| HEX 0x0012 查询/设置（PPS 开关/模式） | bsp_parse.c，无产品 guard | 原生可用 |
| PPSStatus/PPSMode 参数持久化 | ProductInfo_S 位域 + A/B 双页 | 原生可用（507 已入双页 guard） |
| 脉冲回调校准算法 + 模式 2 触发计数 | bsp_pps.c BspPPS1SCallback，全平台共用 | 原生可用 |
| **硬件捕获（引脚/EXTI 中断）** | **主工程，各产品自建** | **本次新增** |
| **上电恢复开关/模式** | **主工程 AppInit** | **本次新增** |
| **时间同步消费校准值** | **bsp_function.c 各产品分支** | **本次新增** |

## 2. 硬件捕获层（drv_pps.c，03.DRV 层，BSP_507_PROJECT guard）

- `DrvPPSInit()`：PA2 下拉输入（HAL `HalGpioInputInit`）→ EXTI2 上升沿
  （`HalExtiInit` + 回调注册）→ EXTI 回调内 **50ms 软件消抖**（无符号差分防节拍回绕）
  → 转发 `BspPPS1SCallback()`（校准计算 + 模式 2 推送触发计数入口）。
- 整体在 `#if defined(BSP_507_PROJECT)` 内，其它平台编译为空，零影响。
- 引脚冲突核查：507 A 口仅 PA4（ICM42688 CS）被占用，PA2 空闲；
  NVIC 优先级组与 HAL 层 uart/timer 统一（PRE2_SUB2，EXTI 优先级 2,0）。

## 3. 上电恢复（app_main.c AppInit 507 段）

`DrvPPSInit()` 后从配置恢复 `BspPPSStatusCtrlSet / BspPPSModeSet`——否则参数里的
开关/模式只在查询接口生效，PPS 运行态上电恒关闭（参照 F1 main.c）。

## 4. 时间同步消费校准值（模式 1 生效的关键）

bsp_function.c 507 分支 `BspSystemTimeSync(BspSysRunTimeGet())` 改为
`BspSystemTimeSync(BspPPSCalibratedUsGet())`：

- PPS 未锁定时校准系数初值（斜率 1/偏移 0）下校准输出与运行时间戳**完全等价**，
  行为无退化；
- 锁定后按 PPS 校准值输出（整秒对齐 + 晶振频偏校正）——模式 1
  "校准内部时间戳"对 507 生效，且**所有推送报文的统一时间戳**（BspPushTimestampGet）
  一并跟随校准值。
- 注意 BspPPSCalibratedUsGet 的单调钳位与 64 位撕裂读保护均为 bsp_pps.c 内建，
  507 无需额外处理。

## 5. 功能矩阵与范围

- 模式 0：空；模式 1：校准内部时间戳（时间同步跟随校准值）；模式 2：每个脉冲沿
  触发一帧 0x0013 推送（BspPPSTriggerConsume 消费计数，推送中心全平台共用）；
- 锁定状态：2s 无脉冲自动失锁（BspPPSLockStatusGet），经 0x0012 查询/0x0013 上报；
- 0x0013 报文含 Timestamp=校准时间/PPSStatus/PPSMode/日历时间，周期订阅+触发双入口；
- **未移植**：F1 的 DrvPPSUartInit（PA3 GNSS NMEA 语句串口，配 bsp_gps）——属 GPS
  模块配套，非 PPS 脉冲功能本体，如需 NMEA 时间源后续再加。

## 6. 实机验证清单

1. PPS 1Hz 信号源接 PA2 → 0x0012 设置开启+模式 1 → 查询返回锁定状态 1；
2. 推送时间戳整秒对齐（日历时间随 PPS 跳秒）；
3. 切模式 2 → 每个脉冲沿触发一帧 0x0013（高频脉冲积压不丢帧，饱和消费）；
4. 拔信号源 2s 后失锁，时间戳按最后斜率平滑外推不回跳。
