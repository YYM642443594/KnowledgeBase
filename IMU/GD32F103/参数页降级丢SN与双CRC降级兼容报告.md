# 参数页降级丢 SN 与双 CRC 降级兼容报告（2026-11-18）

> 涉及版本：V3.0.0.6 降级 → V3.0.0.5；修复随 V3.0.0.7 发布；A/B 双页参数区（bsp_data_interaction.c）
> 关联工程：IMU_103_303_333（共用 BSP_IMU.git 子仓库，335/351/506 同步受益）
> 关联文档：[GD32F303/参数页升级SN乱码与预留区扩展机制报告](../GD32F303/参数页升级SN乱码与预留区扩展机制报告.md)（升级方向的先例与本方案基础）

## 一、问题现象

测试反馈：设备从 V3.0.0.6 降级刷回 V3.0.0.5 后，SN 号等配置参数丢失，恢复为出厂默认值。
升级方向（V3.0.0.5 → V3.0.0.6）一直正常，**仅降级方向丢配置**。

## 二、根因分析

### 2.1 格式背景

V3.0.0.6 在 `ProductInfo_S` 尾部启用 Reserved 区（104B → 204B），参数页 CRC 按
当前 `sizeof` = 204 字节计算并写入页头 `Crc` 字段。

### 2.2 降级丢失链路

旧固件 V3.0.0.5（已发布、不可修改）按**自身 sizeof = 104** 复验新固件写入的页：

1. 读 A/B 页 → CRC(104) ≠ Crc(CRC(204)) → **双页全部判无效**；
2. 兜底裸迁移读 `0x08004400`——该页实为校准偏置数据区而非参数页 →
   `ConfigInitFlag != 0xA5`；
3. 判定无有效配置 → **恢复出厂默认 → SN/配置丢失**。

### 2.3 关键盲区

既有的 L1~L3 回退链（CRC 按 96/100/104 逐级复验 + 按格式迁移）只防
**"旧页新读"（升级方向）**，从未防 **"新页旧读"（降级方向）**。
发布至今的每一次格式演进都只考虑了向前兼容，降级从未被验证。

## 三、修复方案：双 CRC 页

### 3.1 页头布局

`ProductInfoFlash_S` 尾部新增 `ExtCrc` 字段（Data 之后，页偏移 216，总长 220B）：

| 字段 | 计算范围 | 作用 |
|------|----------|------|
| `Crc`（原字段，语义冻结） | **恒按 104B 前缀** | V3.0.0.5 降级后按自身 sizeof=104 复验**直接通过**，识别为"当前格式"整页加载，配置无损 |
| `ExtCrc`（新增） | 当前完整长度 204B | 新固件校验当前格式 |

**对已发布固件零影响**：104B 版读取范围 116B、发布版 V3.0.0.6 读取范围 216B，
均触不到偏移 216 的 ExtCrc；其对 `Crc` 的消费行为（按自身 sizeof 复验）恰好被
冻结后的语义满足。

### 3.2 PageCheck 判定顺序（L2/L1 回退原样保留）

```
crc(204) == ExtCrc          → 当前格式（新固件写入的双 CRC 页）
crc(204) == Crc             → 发布版 V3.0.0.6 单 CRC 页（完整迁移，Reserved 保留）
crc(104) == Crc             → L3 页（前缀迁移，Reserved 清零）
crc(L2)/crc(L1)             → 更早历史页（位域重映射迁移，原逻辑不变）
全部失败                    → 裸迁移兜底（不变）
```

### 3.3 互操作场景推演（全场景无损）

| 页写入方 | 页读取方 | 走的分支 | 结果 |
|----------|----------|----------|------|
| V3.0.0.7（双 CRC） | V3.0.0.5（104B） | crc(104)==Crc →"当前格式" | 干净整页加载，**SN 保留**（本次修复点） |
| V3.0.0.5（104B） | V3.0.0.7 | L3 迁移 | 前缀迁移，SN 保留（原有能力） |
| 发布版 V3.0.0.6 | V3.0.0.7 | crc(204)==Crc | 完整迁移（原有能力） |
| V3.0.0.7 | 发布版 V3.0.0.6 | crc(204)==Crc →"当前格式" | 整页加载（触不到 ExtCrc，无损） |
| V3.0.0.7 | V3.0.0.7 | crc(204)==ExtCrc →"当前格式" | 整页加载 |
| V3.0.0.7 页尾损坏 | V3.0.0.7 | 优雅降级至 L3 前缀迁移 | SN 保留，新字段归零 |

### 3.4 设计陷阱：ExtCrc 禁止放入 Data 内部

曾考虑把 ExtCrc 放进 `Reserved` 槽位以不增页长——不可行：CRC 覆盖范围包含槽位
自身，形成自引用，写入时永远无法同时满足。ExtCrc 必须放在所有 CRC 覆盖范围之外。

## 四、防复发机制（编译期强制）

布局冻结原先只靠注释约定，现以三条文件级 `typedef char[条件]` 断言固化
（bsp_data_interaction.c），违规直接编译失败：

| 断言 | 约束 |
|------|------|
| `ProductInfoPrefixFrozenAssert` | 前缀 ≥ 104B（V3.0.0.5 整页读取范围） |
| `ProductInfoSizeFrozenAssert` | 总长恒 204B（= 104 前缀 + 100 初始预留） |
| `ProductInfoFlashHeaderFrozenAssert` | 页头 12B + Data + 4B ExtCrc，无对齐空洞 |

配套规范（注释 + 本文档）：

- 加字段唯一合法方式：从 Reserved **等量切出**（净零变化，断言通过）；
- `Crc` 语义 = 104B 前缀 CRC，**永不**"修正"回按 sizeof 计算；
- `Crc` 计算长度、`ExtCrc` 页偏移、LEGACY 回退链三者构成跨版本兼容契约，
  任何一项变动须重新推演全部互操作场景并同步更新断言。

**残余风险**：降级到低于 V3.0.0.5 的版本（L2/L1/L0 时代）仍会丢配置——
多代"旧长度 CRC"通道无法同时共存于一个字段，发布流程须限制降级下限为 V3.0.0.5。

## 五、验证

- 编译：IDE F7 构建通过（断言同时验证当前布局 104+100=204B、页头 220B 无对齐问题）
- 实测路径（双向回归）：烧 V3.0.0.7 → 配置 SN → 降级刷 V3.0.0.5 → AT+SN 确认保留
  → 升级回 V3.0.0.7 → 确认配置完整
- 注意：本修复随 V3.0.0.7 发布，**须先在新版本下写入一次参数页**（任意配置变更触发
  落盘）后降级，V3.0.0.5 才能读到兼容页；直接从出厂 V3.0.0.6 页降级仍按发布版分支整页加载，同样无损

## 六、经验教训汇总

| # | 教训 |
|---|------|
| 1 | 版本兼容验证必须**双向**：升级 + 降级。回退链只防"旧页新读"是单侧思维，降级方向同样会出现"格式判无效 → 兜底误迁移 → 恢复出厂"事故链 |
| 2 | 当 CRC 是格式唯一裁决者时，**其覆盖长度即兼容断点**：冻结一条按历史长度计算的 CRC 通道（`Crc`=104B 前缀），等于为降级永久留门 |
| 3 | 降级兼容通道的新增字段必须放在**所有已发布固件读取范围之外**，且不改变旧固件所依赖的任何既有字节——以已发布固件的读取行为为约束边界做推演，而非只看当前固件 |
| 4 | 结构体演进规范靠注释约束必然失效，用编译期断言把规范变成编译错误才是强制力 |
| 5 | CRC 覆盖范围内不允许存在"存自身校验值"的自引用字段，新增校验字段必须置于全部 CRC 覆盖范围之外 |
| 6 | 修复已发布兼容缺陷的版本承载有前提：降级兼容依赖新版本先写入一次参数页，发布说明须注明操作顺序 |
