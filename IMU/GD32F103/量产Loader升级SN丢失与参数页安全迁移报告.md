# 量产 Loader 升级 SN 丢失与参数页安全迁移报告（2026-10-23）

## 一、测试现象

- 量产设备（develop 旧固件）执行量产 Loader 升级后，**SN 序列号丢失**
- 部分场景配置项（波特率、推送配置、量程）同样丢失，重启后回到出厂默认值
- 后续排查发现升级链路还有第二个隐患：**配置后 2 秒内立即复位/升级，配置丢失**

## 二、根因分析

### 根因1：旧参数页地址落在量产 Loader 的擦除范围内

```text
GD32F103T8 Flash 布局（128KB，0x08000000~0x0801FFFF）
0x08000000 ┌──────────────────┐
           │ APP 前                       │
0x08004400 │ 旧参数页（裸 ProductInfo_S）  │ ←★ 与用户校准偏置区共用，
           │                              │   且在 Loader 擦除范围内
0x08004800 ├──────────────────┤
           │ 量产 Loader ROM (8.98KB)     │ ← 升级时硬编码擦除
           │                              │   0x08004800~0x0801FFFF
0x0801FFFF └──────────────────┘
```

- 量产 Loader 升级 APP 时**硬编码擦除到 0x0801FFFF**，旧参数页 0x08004400
  在擦除范围内 → 升级即丢
- 加重因素：0x08004400 与**用户校准偏置区（USER_CALIBRATION_PARAM_2）共用**，
  页内容可能是校准浮点数据而非参数，裸读取会把垃圾数据误当配置迁移

### 根因2：延迟落盘机制下，复位/升级入口未强制落盘

- 配置写入采用**延迟落盘**（见第五节）：`BspProductInfoSaveToFlash()` 仅标脏，
  主循环静默期 **2 秒**后由 `BspProductInfoSaveToFlashProcess()` 统一擦写
- 复位/升级指令（Hex 0x0500 / 0x0014 / 0x0604、AT+RST、CAN 0x110）执行路径
  **未调用 `BspProductInfoSaveToFlashFlush()`** → 静默期内（含 2 秒内）触发
  复位/升级，脏数据未落盘即断电重启，配置丢失

## 三、修复方案

### 1. 参数页迁移至 Loader 擦除范围外的唯一安全区

| 页 | 地址 | 说明 |
|----|------|------|
| 参数页 A | **0x08003000** | 活跃页 |
| 参数页 B | **0x08003400** | 冗余备份页 |
| 旧裸迁移源 | 0x08004400 | 仅旧固件一次性迁移读取，不再写入 |

- 两页均位于量产 Loader ROM（0x08004800 起）**之前的空闲区**，
  升级擦除（0x08004800 以上）**永不触碰**
- **硬约束：任何参数存储地址迁移，必须确保新地址不在 Loader 擦除范围内**

### 2. A/B 双页参数保护（掉电必有一份完整数据）

写入流程（`BspProductInfoWriteToDualPage`）：

```text
构造 ProductInfoFlash_S {Magic="PI35", Sequence+1, Crc32, Data}
  → 写入非活跃页（1KB 页擦除后写入）
  → 校验通过后切换活跃页序号
```

- 页头 12 字节：Magic(4B) + Sequence(4B, 单调递增) + Crc(4B) + 数据
- 读取时双页校验（Magic + CRC32），**双有效取 Sequence 高者**
  （无符号差值 `(int)(SeqA - SeqB) >= 0`，序号回绕安全），
  单有效取该页，双无效走出厂默认/裸迁移
- CRC 失败的场景：写入中途掉电——此时另一页必为上一版完整数据

### 3. 旧格式迁移体系（跨版本升级兼容）

历史参数页格式按写入时 `sizeof` 计算 CRC，需按对应旧长度复验：

| 格式 | 版本 | 特征 | 迁移要点 |
|------|------|------|----------|
| 当前 | V3.0.0.22+ | 含 Reserved[99] 预留区 | 直接使用 |
| L3 | V3.0.0.20~21 | 无预留区，前缀与当前一致 | 拷贝旧长度 104B，预留区清零 |
| L2 | V3.0.0.16~19 | 无 UserCanSimpDataPushCfg/0x0022 位 | 拷贝旧长度 + 位域重映射 + 串口0默认使能 |
| L1 | V3.0.0.14/15 | 另无 AccScale/GyroScale，位域前移 4B | 分段搬运 + 位域重映射 + 标志单独搬 |
| 裸数据 | V3.0.0.13- | 无 Magic 包装直写旧地址 | 0x08004400 读取，**必须 ConfigInitFlag==0xA5 校验**才迁移（防把校准浮点当参数） |

- 位域重映射：旧版无 DataPacket0x0022 位，插入后 PPSStatus/PPSMode/ZeroBias
  整体后移 1 位，按位重映射搬运
- 关键设计：**旧长度一律由当前布局相对推导（offsetof），不使用绝对字节数**——
  枚举容器 ABI 变化会使 sizeof 漂移，绝对值校验会失效

### 4. 配置持久化闭环（复位/升级入口 Flush 兜底）

```text
配置指令 → BspProductInfoSaveToFlash()  仅标脏(G_ProductInfoDirty + Tick)
主循环   → BspProductInfoSaveToFlashProcess()  静默期2秒满且脏 → 擦写落盘
复位/升级 → 应答发出后、复位执行前 → BspProductInfoSaveToFlashFlush() 强制立即落盘
```

- 延迟落盘目的：连续配置指令只落盘一次，避免 UART 传输中擦写 Flash 停转 CPU 丢数据
- **5 个复位/升级入口全部补齐 Flush**：Hex 0x0500（复位）、Hex 0x0014（重启）、
  Hex 0x0604（进升级）、AT+RST、CAN 0x110
- Flush 内部先查脏标记，无脏直接返回——**不会产生无意义的 Flash 擦写**
- Flush 落盘的 Flash 写入停转 CPU 发生在应答发送之后，不影响应答送达
- 注意：配置变更后必须 `BspProductInfoSaveToFlashProcess()` 在主循环被调用
  才会落盘，仅标脏不调用 Process 则断电即丢

## 四、运维注意事项（存量设备补救）

**量产设备（develop 旧固件，参数在 0x08004400）第一次升级新固件，SN 必丢**
（旧地址在 Loader 擦除范围内，无解），需上位机配合补救流程：

1. 升级前查询 SN（留档）
2. 执行量产 Loader 升级
3. 用 0x0602 重写 SN
4. 之后的新固件参数已在新址，升级不再丢

## 五、验证清单

- [x] 烧新固件后重配 + 重写 SN 一次（新参数页首启）
- [x] 配置 + SN → 0x0604 升级 → SN/配置保留（核心）
- [x] 升级后再升级 → 保留
- [x] 量程四入口非法值纠正（AT / Hex 0x0022 / Hex 0x050C / CAN 0x115）
- [x] 0x22 应答负载 10 字节 + 设置回显生效值
- [x] 设置后重启持久化
- [x] 配置后 2 秒内立即发复位/升级指令 → 配置保留（Flush 兜底验证点）

## 六、硬约束（后续开发红线）

1. **Flash 写前必须先扇区擦除**（GD32F103T8 1KB 对齐）
2. **禁止使用 0x08004400 地址**（用户校准偏置数据占用）
3. **任何参数存储地址迁移必须确保不在量产 Loader 擦除范围内**
   （303/333 唯一安全区 0x08003000/0x08003400）
4. 所有设备复位/升级入口必须在**应答后、复位前**调用
   `BspProductInfoSaveToFlashFlush()`
5. `DrvFlashWrite32BitData` 不得引用 `flash.c` 的 API
6. 预留区扩展规则：新增字段只动 Reserved 区间（声明在 Reserved 之前、
   Reserved 减对应字节数），**禁止改动现有字段顺序/类型、禁止在预留区前插入
   字段**——保证 Flash 布局与 CRC 长度恒定，避免再产生旧格式迁移
