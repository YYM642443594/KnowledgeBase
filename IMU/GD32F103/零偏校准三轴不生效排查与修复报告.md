# 零偏校准三轴不生效排查与修复报告（2026-11-18）

## 一、测试现象

零偏校准指令（AT / HEX / CAN / PC 四路）应答流程全部正常（"Calibration successful" +
Flash 保存），但 CAN 推送的角速度零偏抑制效果异常。经三轮递进修复，现象演进如下：

| 阶段 | X | Y | Z | 表现 |
|------|---|---|---|------|
| 修复①前 | 无效 | 无效 | 无效 | 校准成功但推送数据无任何变化 |
| 修复①后 | 无效 | 无效 | 生效 | 只对角速度 Z 有用 |
| 修复②后 | 生效 | 无效 | 生效 | X/Z 有用，Y 无用 |
| 同固件再次校准 | 残差 −1.9965°/s | 残差 0.3041°/s | 0.0009°/s | Y 好转，X 反而劣化 |
| 修复③后 | 生效 | 生效 | 生效 | 一次校准三轴全部归零 |

**关键线索**：残差不是固定在某一个轴，而是**每轮校准在 X/Y 之间轮转**（幅值同量级
约 2°/s），Z 轴自始至终完美收敛（0.0009°/s 级）。这个"轮转"特征直接指向零偏被
**坐标系旋转错位**。

## 二、根因分析：三层"域不一致"叠加

零偏校准闭环的本质要求：**估计域 = 扣除域 = AHRS 输入域**，三者缺一不可。
校准库 nav_fusion 的 `simpleUserCalibration`（反汇编实证）行为：

- 不读取传入参数（仅作输出缓冲）；
- 估计值 = 喂给 `updateAhrsFilter` 的陀螺经库内 IIR 的滑动均值（累计 200 样本）；
- 该估计值**单位是 rad/s**（库内自带 °/s→rad/s 换算）；
- 被均值化的陀螺处于**坐标转换之后**的处理域。

本工程（IMU_103_303_333）全链口径：陀螺 °/s（`GYRO_SCALE = 量程/32768`，无 π/180
因子），加速度 m/s²。三层根因分别破坏了上述三个"同域"：

### 根因① 单位不一致：库返回 rad/s，工程全链 °/s

累加时直接 `UserCalibrationBias[i] += est`，未乘 `RAD_TO_DEG` → 修正量缩小
57.3 倍 → 表现为校准流程完整走完但推送数据看不出效果（对应修复①）。

### 根因② 估计域与观测域温补不一致

修复①后姿态链喂给库的陀螺取的是**未温补**数据，而推送路数据是**温补后**的。
温度补偿按轴独立进行，两路的补偿差直接成为估计误差 → 温补参数差异大的轴校准
无效（对应修复②：`G_GyroRaw` 改存温补后未滤波数据，估计/扣除/AHRS 输入统一
温补域，X/Z 随即生效）。

### 根因③ 扣除顺序与估计域不一致（坐标转换）—— X/Y 轮转真凶

修复②后两条链路仍是**先扣零偏 → 后坐标转换**，而库在**坐标转换之后**的域估计。
设坐标系转换为带符号轴置换矩阵 P，存储零偏 s（转换前域），转换前域真实零偏 b，
则库估计到的是输出域残差：

```text
est = P·(b − s)          （转换前扣除量经 P 错位映射到输出域）
s'  = s + est
e'  = b − s' = (I − P)·e  （误差迭代式）
```

坐标系 200（out_x=in_y, out_y=−in_x, out_z=in_z）的 XY 子块
P = [[0,1],[−1,0]]，(I−P) 的特征根为 1±i，**模长 √2 ≥ 1**：

- XY 误差每轮**旋转 45° 且放大 √2 倍**，迭代永不收敛——零偏被反复旋转错位重新
  分配到 X/Y 两轴；
- **Z 是 P 的不动轴**（特征根 1），(I−P) 在 Z 子空间恒为零 → 一轮即精确收敛
  ——这就是 Z 轴自始至终完美的原因。

每轮校准指令入口都会把 `UserCalibrationBias` 清零（bsp_parse.c 四路指令入口），
故迭代逐轮重置、不表现跨轮放大；错位轮转来自一轮校准后的残差公式（s 从 0 起，
est=P·b）：残差 = (P−P²)·b，即 **X 残差 = bx+by、Y 残差 = by−bx**——两轴残差是
物理零偏的线性组合，叠加物理零偏随温度/上电状态漂移与估计噪声，宏观表现即
"残差逐轮在 X/Y 间轮换"。

参考工程 IMU_350_301_331 的 `bsp_algorithms.c` 对此早有实测注释存档：
**"坐标系非100时转换前扣除会使扣除量被旋转错位(200配置实测X轴扣成Y轴零偏)"**
——本例完整复现了该现象。

## 三、修复方案（bsp 子仓库 00.Code/src/bsp_algorithm.c）

### 修复① 累加补乘 RAD_TO_DEG（303/333 条件编译）

```c
#if defined(BSP_303_333_PROJECT) /* 本工程陀螺全链为°/s, 库估计值为rad/s,
                                    不换算则修正量缩小57.3倍 */
    pProductInfo->UserCalibrationBias[i] += user_calibration_bias_2[i] * BSP_ALGORITHM_RAD_TO_DEG;
#else
    pProductInfo->UserCalibrationBias[i] += user_calibration_bias_2[i];
#endif
```

### 修复② 统一温补域

`BspSensorDataProcess` 中 `G_GyroRaw[i] = gyro_out[i]`（温补后未滤波，原为未温补
原始数据）；姿态链零偏校准输入随之统一为温补域。

### 修复③ 先坐标转换后扣零偏（推送链 + 姿态链 + 校准采样点随迁）

姿态链（关键：校准采样点必须与 AHRS 输入同域）：

```c
IMUConvertData.gyro_x = gyro_data[0];              /* 1.先不扣偏 */
...
BspCoordinateSystemConvert(&IMUConvertData);       /* 2.先坐标转换 */
gyro_data[0] = IMUConvertData.gyro_x - pProductShadowInfo->UserCalibrationBias[0]; /* 3.后扣零偏 */
...
BspZeroBiasCalibrationProcess(gyro_data);          /* 4.校准采样 = AHRS 输入, 同域 */
```

推送链同样改为转换后扣偏：`G_ArithmeticData.Gyro[i] = FltrConvertData.gyro_x[i]
- UserCalibrationBias[i]`。

坐标系 = 100（恒等阵 P=I）时新旧顺序数学等价，本修改无回归风险；坐标系 ≠ 100 时
必须如此。修复后与参考工程 IMU_350_301_331 架构完全对齐，一次校准三轴全部收敛。

## 四、约束规范（后续红线）

1. **零偏闭环三同域铁律**：估计域 = 扣除域 = AHRS 输入域；三个维度分别核对——
   单位（rad/s ↔ °/s）、温补（补前/补后）、坐标（转换前/转换后）。
2. **零偏扣除必须在坐标转换之后**；新增坐标系配置（P≠I）时，先转换后扣偏的
   顺序不可回退。
3. 跨库/跨工程复用校准库前先确认三点：库估计单位、库采样域、工程数据链单位
   （本例 57.3 倍即单位漏检的典型代价）。
4. 校准类问题优先用诊断日志裁决：校准完成时打印 est/total 三轴值——est 非零但
   推送无变化 → 扣除/域问题；est≈0 → 估计链路问题；残差逐轮换轴 → 坐标转换
   错位特征。
5. 对齐参考工程是捷径：IMU_350_301_331 的 `bsp_algorithms.c` 注释存档了本例全部
   三个坑（RAD_TO_DEG 换算、温补域统一、转换后扣偏）。
