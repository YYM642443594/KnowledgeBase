## 1. 快速开始

首次使用或日常新增文档，按以下步骤操作即可：

1. **克隆仓库**（仅首次）：`git clone https://github.com/YYM642443594/KnowledgeBase.git`，本机已有副本则跳过；
2. **选择分类**：根据内容类型进入对应目录（分类说明见第 4 节）；
3. **新建文档**：复制 `00-索引/模板-知识文档.md` 到目标目录，并按第 5 节规范命名；
4. **撰写内容**：填写元信息（创建日期、标签），正文遵循「先结论，后细节」；
5. **登记索引**：在 `00-索引/索引.md` 对应分类下添加一行链接；
6. **提交推送**：

```bash
git add -A
git commit -m "新增：<文档标题>"
git push
```

## 2. 知识库简介

本知识库用于**系统化地收集、整理和沉淀个人/团队的知识资产**，包括学习笔记、技术文档、项目经验、问题解决方案、参考资料等。

### 2.1 目标

- **结构化**：所有知识按统一规则分类存放，便于查找。
- **可追溯**：文档记录来源与更新时间，方便回溯。
- **可复用**：沉淀的经验和方案可以被反复查阅和使用，避免重复劳动。
- **易维护**：规范命名与格式，降低长期维护成本。

### 2.2 适用范围

- 个人学习笔记与技术积累
- 项目文档与经验总结
- 常见问题与解决方案（FAQ / Troubleshooting）
- 外部资料的摘录与整理（需注明来源）

## 3. 目录结构

知识库采用以下目录结构（可根据实际需要增删调整，调整后请同步更新本文档）：

```text
KnowledgeBase/
├── README.md                 # 本说明文档（人类向完整规范）
├── AGENTS.md                 # AI Agent 工作规范（跨工具标准，agent 必读）
├── CLAUDE.md                 # Claude Code 入口，自动加载并引用 AGENTS.md
├── 00-索引/                   # 知识库总索引、导航页、文档模板
│   ├── 索引.md
│   └── 模板-知识文档.md
├── 01-技术笔记/               # 技术学习笔记（按领域细分）
│   ├── 编程语言/
│   ├── 前端/
│   ├── 后端/
│   ├── 数据库/
│   ├── 运维与部署/
│   └── AI与数据/
├── 02-项目文档/               # 具体项目的设计、方案、总结
├── 03-问题排查/               # Bug 记录、故障排查、解决方案
├── 04-工具使用/               # 软件工具、环境配置、效率工具
├── 05-读书笔记/               # 书籍、课程、文章的阅读笔记
├── 06-参考资料/               # 外部资料收集与整理
├── 07-日常记录/               # 日志、周报、灵感与备忘
├── 90-归档/                   # 已过时或不再维护的文档
├── assets/                    # 附件与图片资源
│   ├── images/                # 图片
│   └── files/                 # 其他附件（PDF、压缩包等）
└── .gitignore                 # Git 忽略规则
```

> **说明**：目录编号（`00-`、`01-` 等）用于控制排序，不代表重要性。空目录中出现的 `.gitkeep` 仅用于让 Git 跟踪空目录，可随内容增加删除。

## 4. 分类说明

| 目录 | 用途 | 收录内容示例 |
|------|------|-------------|
| `00-索引/` | 全库导航 | 总目录页、文档模板、标签索引 |
| `01-技术笔记/` | 技术知识沉淀 | 语法笔记、框架用法、算法总结、命令速查 |
| `02-项目文档/` | 项目相关产出 | 需求分析、架构设计、上线方案、复盘总结 |
| `03-问题排查/` | 问题与解决 | Bug 分析过程、报错信息及解决办法、踩坑记录 |
| `04-工具使用/` | 工具类知识 | 软件安装配置、快捷键、使用技巧 |
| `05-读书笔记/` | 阅读积累 | 书摘、读后感、课程笔记 |
| `06-参考资料/` | 外部资料 | 优质文章转载、链接汇总、官方文档要点 |
| `07-日常记录/` | 日常零散记录 | 工作日志、待办备忘、灵感碎片 |
| `90-归档/` | 历史存档 | 过时但仍有参考价值的旧文档 |
| `assets/` | 静态资源 | 文档中引用的图片、附件 |

**归类原则**：

1. 一篇文档只放在**一个**最合适的目录下，通过链接和标签建立关联。
2. 拿不准放哪里时，先放入最接近的分类，后续定期整理时再调整。
3. 持续 6 个月以上未更新且失去时效性的文档，移入 `90-归档/`。

## 5. 命名规范

### 5.1 文件命名

- 使用 **中文或英文均可**，但同一目录内保持风格统一。
- 语义清晰，能从文件名看出文档主题，避免 `新建文档`、`笔记1`、`未命名` 等名称。
- 文件名中**不要包含**空格和特殊字符（`/ \ : * ? " < > |`），多个单词可用 `-` 或 `_` 连接。
- 带日期的记录类文档，日期统一使用 `YYYY-MM-DD` 格式并置于文件名开头，便于排序。

**命名示例**：

```text
✅ Git-常用命令速查.md
✅ 2026-09-15-数据库连接超时排查.md
✅ Python-异步编程笔记.md
❌ 新建文本文档.md
❌ notes final(2).md
```

### 5.2 图片与附件命名

- 存放在 `assets/images/` 或 `assets/files/` 下。
- 建议以「所属文档名 + 说明」命名，如 `Git-常用命令-rebase流程图.png`。

### 5.3 标签规范

- 每篇文档选取 **2~5 个**标签，写在文档头部 YAML front-matter 的 `tags` 字段中，格式：`tags: [Git, 版本管理]`。
- 标签使用简短的名词或名词短语，中英文均可；同一概念保持同一种写法（如统一用 `Git`，不要混用 `git`、`GIT`）。
- 新标签首次使用后，登记到 `00-索引/索引.md` 的「标签索引」中，避免同义标签泛滥。

### 5.4 文档标题

- 文档内的一级标题（`#`）应与文件名主题一致。
- 正文标题层级从 `##` 开始，逐级递增，不跳级。

## 6. 文档编写规范

### 6.1 基本格式

- 统一使用 **Markdown**（`.md`）编写。
- 使用 UTF-8 编码，换行符不作强制要求。
- 中文与英文、数字之间建议加一个空格（如「使用 Git 管理」），提高可读性。

### 6.2 结构要求

一篇完整的知识文档建议包含以下部分：

1. **标题**：一句话说明主题；
2. **元信息**：YAML front-matter 形式的 `title` / `created` / `updated` / `tags` / `source`（详见模板），便于人与工具统一解析；
3. **概述**：简述文档解决什么问题、适用场景；
4. **正文**：核心内容，善用列表、表格、代码块、图示；
5. **参考链接**：引用的外部资料来源。

### 6.3 内容原则

- **先结论，后细节**：把最重要的结论放在开头。
- **代码必带说明**：代码块标注语言类型，并说明关键步骤。
- **记坑要记全**：记录问题时包含「现象 → 原因 → 解决方案 → 预防措施」。
- **注明来源**：转载或摘录的内容必须标注原文出处和链接。
- **定期回顾**：发现内容过时及时更新，而不是另建新篇。

### 6.4 代码块示例

````markdown
```python
# 示例：快速排序
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[0]
    left = [x for x in arr[1:] if x < pivot]
    right = [x for x in arr[1:] if x >= pivot]
    return quick_sort(left) + [pivot] + quick_sort(right)
```
````

## 8. 使用与维护流程

### 8.1 新增文档

1. 判断文档类型，选择合适的分类目录；
2. 复制模板（见第 7 节）创建新文档，按规范命名；
3. 编写内容并填写元信息（日期、标签）；
4. 在 `00-索引/索引.md` 中登记新文档链接；
5. 提交到 Git 并推送（命令见第 1 节快速开始）。

### 8.2 更新文档

- 修改内容后同步更新文档头部的「更新日期」；
- 重大修改可在文档末尾追加「修改记录」。

### 8.3 定期维护（建议每月一次）

- 检查失效链接、过期内容并修正；
- 将过时文档移入 `90-归档/`；
- 整理零散的日常记录，将有价值的内容沉淀为正式文档；
- 更新索引页，保证导航准确。

### 8.4 远程同步

- 远程仓库：<https://github.com/YYM642443594/KnowledgeBase.git>；
- 本地仓库已配置 `origin` 指向该地址，日常同步只需 `git pull` / `git push`；
- 首次推送前，请确认该仓库已在 GitHub 上创建，并配置好访问权限（HTTPS 推送需使用 Personal Access Token 或已配置的凭据）；
- 建议每完成一篇文档或每次整理后提交一次，提交信息格式：`新增：xxx` / `更新：xxx` / `整理：xxx`。

## 10. AI Agent 接入

本知识库对 AI 编码助手（Claude Code、Codex、Cursor 等）开箱即用：

- **`AGENTS.md`**（仓库根目录）：面向 agent 的精简工作规范，涵盖目录选择、命名、索引登记、链接格式与禁止事项，是各类 agent 工具的事实标准入口文件；
- **`CLAUDE.md`**：Claude Code 启动时自动加载的入口，内容为 `@AGENTS.md`，直接引用上述规范，保证单一来源、不会失同步。

### 10.1 Agent 的工作方式

1. Agent 进入仓库后先读取 `AGENTS.md`（Claude Code 通过 `CLAUDE.md` 自动完成），无需人工转述规则；
2. 新增 / 修改文档时，agent 按「复制模板 → 填 YAML 元信息 → 规范命名 → 登记索引 → 提交」的固定流程执行；
3. 所有约束（相对链接、注明出处、索引同步等）在 `AGENTS.md` 中以硬性规则列出，agent 必须遵守。

### 10.2 人工使用建议

- 让 agent 写文档时，只需说明主题与内容要点，无需重复目录、命名等规则；
- 对 agent 的特殊要求（如「移入归档」「改目录结构」）直接在对话中说明即可，`90-归档/` 与结构性调整默认需要人工确认；
- 修改本库规范时，**只改 `AGENTS.md` 和 `README.md`**，保持 `CLAUDE.md` 只含引用行。

## 11. 常见问题（FAQ）

**Q1：一篇文档涉及多个分类，放哪里？**

A：放在**最主要**的那个分类下，其他分类通过索引或链接引用，避免多处存放导致内容不同步。

**Q2：日常零散的想法怎么记？**

A：先记在 `07-日常记录/` 下的日志文件中；定期回顾时，把有价值的内容整理成正式文档移入对应分类。

**Q3：文档写错了分类或命名怎么办？**

A：直接移动 / 重命名，并同步更新索引页中的链接。

**Q4：外部转载的资料如何处理？**

A：放入 `06-参考资料/`，注明原文作者、出处链接与转载日期；重要内容建议附上自己的理解和摘要。

**Q5：什么样的文档应该归档？**

A：内容明显过时、不再维护、但偶尔可能有参考价值的文档，移入 `90-归档/`；完全无用的文档可直接删除（若使用 Git，历史版本仍可找回）。

**Q6：怎么让 AI agent 按本库规范写文档？**

A：无需额外说明。agent 进入本仓库会自动读取 `CLAUDE.md`（引用 `AGENTS.md`），已知晓目录、命名、模板与索引规则；直接告诉它主题和要点即可。对规范本身的修改请编辑 `AGENTS.md` 与本文档。
