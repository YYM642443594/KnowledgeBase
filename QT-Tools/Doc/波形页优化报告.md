# 实时波形页优化报告（2026-10-10）

用户反馈两个问题：①软件运行一段时间后卡顿；②波形页 Y 轴量程固定，看不出实时变化。
本文档记录根因、修复方案与实测证据。gitee 提交：波形页重构（develop，2026-10-10）。

## 一、卡顿根因（三个，全部修复）

### 1. rebuildNeeded 全清重建尖峰（主因）
- 后端 `DataPlotViewModel` 存储裁剪到 1500 点后发 `rebuildNeeded`，
  旧 QML 收到后 `resetChart()` 清空全部 series，下一 tick 一次性重建
  4 图 × 3 系 × 1500 点 = **1.8 万点** → 主线程阻塞尖峰。
- 修复：`updateChart()` 改为**整窗重绘**（同一 JS 块内 `clear()+append(批量)`，
  场景图只同步一次）。裁剪对组件透明，`onRebuildNeeded` 监听整个删除。

### 2. remove(0,n) 前删 O(n)
- 旧代码每 tick 追加新点后从 series 头部删除旧点（O(n) 搬移+整缓冲重传）。
- 修复：整窗重绘天然消除索引/前删状态。

### 3. DebugPage 隐藏页日志全量过滤（设备场景）
- DebugPage 位于 StackLayout（非 Loader），`onLogsChanged → syncLogs → rxLogs()`
  对 `mainVM.logs`（QVariantMap 列表）做 **O(上限) 全量过滤+JS 重建**，无可见性守卫。
  设备 50Hz 推流时即使停在波形页也被逐帧唤醒——"运行一段时间后卡顿"的来源
  （日志滚动窗口填满后成本恒定在满量）。
- 修复：`if (!root.visible) { logDirty = true; return }` + `onVisibleChanged` 补同步
  （seq 增量机制天然支持，切回页面看到离开期间的全部日志，XCOM 行为不变）。

## 二、Y 轴固定 → 自适应

- 旧：固定量程（角速度 ±500°/s、静态噪声 ±1°/s 仅占画布 0.2% → 视觉直线）。
- 新：`autoScaleY`（默认开）——可见窗口数据 min/max + 15% 边距，吸附 **1-2-5 nice 刻度**
  （约 4 主刻度），迟滞策略：数据越界立即扩、范围大于目标 2.5 倍才缩，避免轴抖动。
- 图例带**实时数值**（彩色等宽字体），网格线可见，线宽 2px，Y 轴标签精度随量程自适应
  （≥200 → %.0f、≥20 → %.1f、否则 %.2f）。一键"自适应Y:开/关"切回固定量程。
- 自适应数学已用运行时插桩逐字验证：数据 [-3.75,2.98]→轴[-5,5]、[-4.12,9.11]→[-10,15]、
  [-75.0,49.6]→[-100,100]。
- X 窗口自适应：`min(windowSec=30s, 数据跨度)`，启动初期自动放大细节。

## 三、顺带修复：模拟数据 float 精度 bug

`onSimulateTimeout` 用 `float t = timestamp/1000.0f`（epoch 秒 ≈1.79e9，float 步长 128s）
→ 所有模拟值恒定、曲线为水平直线。改为相对时间基准 `m_simStartTimestamp`；
yaw 由无界斜坡 `t*10` 改为 `fmod(t*20, 360)`。

## 四、实测证据（同机 30s / 模拟 100Hz / QSG_RENDER_TIMING）

| 指标 | 旧代码 | 新代码 |
|---|---|---|
| sync（主线程阻塞）≥10ms 次数 | **15** | **2**（含启动 1 次） |
| sync ≥20ms | 11 | 1（启动） |
| sync p99 | 8ms | 4ms |
| 稳态 sync 最大 | 32ms | ~5ms |
| sync 平均 | 0.64ms | 0.63ms |
| render 平均 | 1.25ms | 2.06ms（整窗重传的 GPU 代价，不阻塞 UI） |

- 旧代码尖峰节奏 ≈ 每 2s 一次（对应 rebuild 周期），稳态突发簇 21-32ms。
- 抓屏像素分析：旧=各系列单条 40px 扁平线；新=曲线纵向铺开 ~100px/230px 画区（≈43%，
  与 ±5 数据在 ±10 nice 量程的预期 50% 吻合）。
- 证据 PNG（开发机 workspace）：`wave-baseline2.png`（旧·平线）、`wave-after3.png`（新·自适应波形）。

## 五、自测钩子（回归验证用）

```
CommTools.exe --simulate --seconds 30 --grab out.png    # 100Hz 模拟数据+波形页+抓屏
# 外部设 QSG_RENDER_TIMING=1，帧耗时写入 exe 目录 debug.log
# 解析：Select-String 'frame rendered in' + 正则 'sync=(\d+)'
```
注意：QML 调 C++ setter 须用属性赋值（`vm.simulating = true` 走 Q_PROPERTY WRITE），
直接调 `setSimulating()` 会因非 Q_INVOKABLE 抛 TypeError（曾致测试空跑，已踩坑）。
另：QML 不允许给未声明属性赋值（"Cannot assign to non-existent property"）。

## 六、遗留

- COM8 实机体验建议用户确认（GUI 无法自动开串口自测；模拟路径与实机共用同一渲染管线，
  且数据率更高）。
- DebugPage 可见时的日志链路仍是 O(上限) 过滤/次——可改为增量 `logAppended(entry)` 信号，
  列为后续优化项。

## 八、用户反馈迭代三（同日 12:41）：X/Y 轴刻度字号自适应

诉求：全部展开时轴文字部分看不清。排查发现两层根因：

1. **QtGraphs 2D 轴无 labelFont 属性**（QAbstractAxis 只有 labelDelegate: Component）。
   刻度文字样式须经 `labelDelegate: Text { color; font.pixelSize }` 设置；
   官方文档：delegate 应为 Text 或含 `property string text`（框架对其赋值）。
2. **GraphsView 刻度拥挤时会整行隐藏**：窗口 1200×800 四图全展开（每图 ~150px）时
   默认固定字号刻度全部被隐藏（debug.log 证实 delegate 实例 vis=false）——这才是
   “看不清”的根源；1920×1040 下同密度刻度正常渲染。

修复（gitee 1756dd0）：

- `axisFontPx = clamp(round(graphsView.height / 18), 9, 16)`，X/Y 轴共用；
  全部展开→9px 保刻度不被隐藏；单图放大→16px。深灰 #475569 提升白底对比度。
- main.cpp 自测钩子新增 `--size WxH`（如 1920x1040）验证不同布局。
- 验证：1920×1040 抓屏 Y 标签带 18-21 物理 px（≈13 逻辑 px，与公式吻合）、
  1200×800 下更小更少（GraphsView 拥挤管理），两尺寸 0 QML 错误。

踩坑记录：

- delegate 在窗口构建期创建（此时 graphsView.height=0，字号绑定初始为下限），
  字号须用绑定而非创建期快照，布局完成后自动更新；框架后续夏用实例并赋 text
  （630 次 text 更新 vs 96 次创建）。
- 像素验证脚本必须按 DPR 换算物理坐标（本机 grab：1920×1040→2884×1760=DPR1.5；
  1200×800→2400×1600=DPR2），否则窗口错位全部扫空。
- GraphsView 红色曲线(#EF4444)会命中“红色文字”像素判定（R>170,G<90,B<90），
  探针配色需避开系列色（纯蓝#0000FF 可与系列蓝#3B82F6 区分：G 通道 0 vs 130）。
