# 页面切换卡顿优化报告（P0 + P1/P2 批次）

日期：2026-10-15 · 分支 develop · 工程仓库：gitee QT-Tools

## 问题现象

串口数据接入后，在不同页面间快速来回切换时出现明显卡顿。

## 根因分析（三源叠加 + Debug 放大）

1. **数据绑定转换风暴（主因）**：`DataPlotViewModel` 13 个数据列表属性（`QVariantList`）共用一个 `dataChanged` NOTIFY。波形页 4 张图 × 4 数组绑定 = 16 个 `property var` 绑定，每次 `dataChanged` 都全量重转换：1500 点 × 16 ≈ **24000 次 QVariant→JS 装箱转换/次**。触发源：10Hz 刷新定时器 + 每次进入数据页 `setViewActive(true)` 的立即 emit。绑定不受页面可见性门控，停在主图数据页时，隐藏的波形图绑定照常全量烧。
2. **调试页日志全量拷贝**：`mainVM.logs` 为 QVariantList（上限 5000 条 QVariantMap）。DebugPage `syncLogs() → rxLogs()` 每次全量读取并逐条深度转换为 JS 再过滤 RX。串口流下每 500ms `logsChanged` 一次；切回调试页 `onVisibleChanged` 再补一次突发。
3. **七页全量常驻（本批未改，P1 项）**：StackLayout 七页启动即全部实例化（仅波形页 Loader 延迟），每次切页全树可见性切换 + 布局重排，Quick3D 场景显隐还触发场景同步。
4. **放大器**：日常运行为 Debug 构建（MSVC /Od 无优化 + Qt Debug DLL）。

# B7 批次（2026-10-15 第三轮，提交 da861cb）：调试页流畅度 + 面板切换卡顿

## 问题与根因

1. **调试页接收显示不如 XCOM 流畅**：日志/字节计数刷新定时器 500ms（2Hz），批量跳变不跟手。
2. **疯狂切换串口/蓝牙配置面板卡顿**：侧栏本身已是双常驻 Loader（只切 visible，非重建）；根因是每次展开串口面板 `refreshSerialPorts() → mainVM.availablePorts()` 在 UI 线程同步调 `QSerialPortInfo::availablePorts()`——Windows 上要走注册表/设备管理器，单次 10-100ms，快速切换即卡。

## 修复

| # | 修改 | 说明 |
|---|------|------|
| 1 | CommViewModel 日志定时器 500→**100ms（10Hz）** | P0 增量拉取后单批成本 O(新增条目)，提频无全量拷贝代价；字节计数同步 10Hz，XCOM 级跟手 |
| 2 | `MainViewModel::refreshSerialPortsAsync()` + `serialPortsReady(QStringList)` 信号 | QtConcurrent 后台线程枚举，QPointer guard + QueuedConnection 回 UI 线程；MainView 面板展开/刷新按钮改走异步，`onSerialPortsReady` 更新 serialPortList |

- `[serial] serialPortsReady count= 4 QList("COM3","COM1","COM6","COM5")`——异步链路端到端工作
- perf_log 新旧对比：旧 #900→#950 间隔 25s（500ms）；新 50 tick/5s（100ms）✓
