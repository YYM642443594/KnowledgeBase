# 协议开发规范

## 1. 概述

本文档定义了 IMU 协议开发的标准规范，包括协议文档编写规范和代码实现规范。遵循此规范可以快速完成新协议的添加或现有协议的修改。

---

## 2. 协议文档编写规范

### 2.1 文档结构

协议文档必须包含以下章节：

| 章节 | 标题 | 内容要求 |
|------|------|----------|
| 3.2.2 | 输入有效数据定义规则 | 指令总览表 |
| 3.2.3.X | 指令详细定义 | 每个指令的发送/回复结构 |

### 2.2 指令总览表格式

**位置**: `3.2.2 输入有效数据定义规则`

表格必须包含以下列：

| 报文ID | 名称 | Cmd | SubId | 支持操作 |
|--------|------|-----|-------|----------|
| 0x00 0x03 | 版本查询 | 0 | 0x03 | 查询 |
| 0x00 0x04 | 传感器数据推送频率设置与查询 | 0 | 0x04 | 查询/RAM/FLASH |
| ... | ... | ... | ... | ... |

**规范要求**:
- 报文ID第二字节（SubId）**必须使用十六进制**表示（如 `0x03`、`0x11`）
- Cmd 值使用十进制（0 或 1）
- 支持操作从以下选项中选择：查询、RAM、FLASH、查询/RAM、查询/FLASH、查询/RAM/FLASH

### 2.3 指令详细定义格式

**位置**: `3.2.3.X 指令名称`

每个指令必须包含以下内容：

#### 2.3.1 发送结构

| 字段 | 偏移 | 长度 | 类型 | 说明 |
|------|------|------|------|------|
| DATA1 | 7 | 1 | unsigned char | 开关状态 |
| DATA2 | 8 | 1 | unsigned char | PPS模式 |
| Reserved | 9 | 8 | unsigned char[8] | 预留 |
| CRC16 | 17 | 2 | unsigned short | |

#### 2.3.2 回复结构

| 字段 | 偏移 | 长度 | 类型 | 说明 |
|------|------|------|------|------|
| DATA1 | 6 | 1 | unsigned char | 开关状态 |
| DATA2 | 7 | 1 | unsigned char | PPS模式 |
| Reserved | 8 | 8 | unsigned char[8] | 预留 |
| CRC16 | 16 | 2 | unsigned short | |

**规范要求**:
- 偏移从 0 开始计数
- 类型必须使用标准 C 类型（unsigned char, unsigned short, unsigned int, float 等）
- 预留字段必须标注 `Reserved`
- 必须包含 CRC16 字段

## 3. 代码实现规范

### 3.1 文件位置

| 文件 | 职责 |
|------|------|
| `bsp/Help/DataParser.h` | 定义数据结构 |
| `ViewModel/CommandViewModel.cpp` | 实现指令注册、发送、接收处理 |

### 3.2 结构体定义规范

**位置**: `bsp/Help/DataParser.h`

**命名规则**: `Hex{名称缩写}{Cmd}{SubId}_S`

**格式要求**:
- 使用 `typedef struct` 语法
- 必须包含 `user_head_t head` 字段
- 字段顺序与协议文档一致
- 最后必须包含 `quint16 Crc16` 字段
- 使用 `#pragma pack(push, 1)` 和 `#pragma pack(pop)` 确保字节对齐

**示例**:

```cpp
/* PPS开关控制 0012 */
typedef struct
{
    user_head_t head;   ///< 协议头部
    quint8 CtrlStatus;  ///< PPS开关状态 0:关闭 1:开启
    quint8 PPSMode;     ///< PPS模式 0:无效 1:PPS校准内部时间戳
    quint8 Reserved[8]; ///< 预留
    quint16 Crc16;      ///< CRC16校验
} HexPPS0012_S, *pHexPPS0012_S;
```

### 3.3 指令注册规范

**位置**: `CommandViewModel.cpp initCommands()`

**格式要求**:
- 使用 `QVariantMap` 注册指令
- `subId` **必须使用十六进制**值
- `id` 为显示序号（十进制，按顺序递增）
- `label` 和 `description` 使用 `QString::fromUtf8()` 包装

**示例**:

```cpp
group0.append(QVariantMap{
    {"id", 18}, 
    {"label", QString::fromUtf8("PPS开关控制")}, 
    {"cmd", 0}, 
    {"subId", 0x12},   // ⚠️ 必须使用十六进制
    {"description", QString::fromUtf8("PPS开关控制")}
});
```

### 3.4 发送数据构建规范

**位置**: `CommandViewModel.cpp buildPayload(quint8 cmd, quint8 id)`

**格式要求**:
- `case` 值 **必须使用十六进制**
- 根据协议文档的发送结构构建 payload
- 预留字段填 0
- 返回 `QByteArray`

**示例**:

```cpp
case 0x12:  // ⚠️ 必须使用十六进制
{
    QByteArray payload(10, 0);
    payload[0] = static_cast<char>(data1Value & 0xFF);
    quint8 data2Value = parseHexValue(m_selectedData2);
    payload[1] = static_cast<char>(data2Value & 0xFF);
    return payload;
}
```

### 3.5 回调数据处理规范

**位置**: `CommandViewModel.cpp handleReceivedData(quint8 cmd, quint8 id, const QByteArray &data)`

**格式要求**:
- `case` 值 **必须使用十六进制**
- 使用对应结构体解析数据
- 格式化输出文本，包含类型名称、字段值、CRC16
- 预留字段显示为十六进制

**示例**:

```cpp
case 0x12:  // ⚠️ 必须使用十六进制
{
    HexPPS0012_S ppsPacket = CommImpl::ByteArrayToStructure<HexPPS0012_S>(data);
    text += QString::fromUtf8("【类型】: PPS开关控制\n");
    text += QString::fromUtf8("开关状态: %1\n").arg(ppsPacket.CtrlStatus == 1 ? QString::fromUtf8("开启") : QString::fromUtf8("关闭"));
    text += QString::fromUtf8("PPS模式: %1\n").arg(ppsPacket.PPSMode == 1 ? QString::fromUtf8("PPS校准内部时间戳") : QString::fromUtf8("无效"));
    QByteArray reservedData(reinterpret_cast<const char *>(ppsPacket.Reserved), 8);
    QString reservedHex = reservedData.toHex().toUpper();
    text += QString::fromUtf8("预留: %1\n").arg(reservedHex);
    text += QString::fromUtf8("CRC16:    0x%1\n").arg(ppsPacket.Crc16, 4, 16, QChar('0')).toUpper();
    break;
}
```

### 4.2 模板代码

#### 模板1：结构体定义

```cpp
/* {指令名称} {Cmd}{SubId} */
typedef struct
{
    user_head_t head;   ///< 协议头部
    // 按协议文档顺序添加字段
    quint8 Reserved[8]; ///< 预留
    quint16 Crc16;      ///< CRC16校验
} Hex{名称缩写}{Cmd}{SubId}_S, *pHex{名称缩写}{Cmd}{SubId}_S;
```

#### 模板2：指令注册

```cpp
group{Cmd}.append(QVariantMap{
    {"id", 显示序号}, 
    {"label", QString::fromUtf8("{指令名称}")}, 
    {"cmd", {Cmd}}, 
    {"subId", 0x{SubId}},   // ⚠️ 必须使用十六进制
    {"description", QString::fromUtf8("{描述}")}
});
```

#### 模板3：发送数据构建

```cpp
case 0x{SubId}:  // ⚠️ 必须使用十六进制
{
    QByteArray payload({长度}, 0);
    // 设置数据字段
    return payload;
}
```

#### 模板4：回调数据处理

```cpp
case 0x{SubId}:  // ⚠️ 必须使用十六进制
{
    Hex{名称缩写}{Cmd}{SubId}_S packet = CommImpl::ByteArrayToStructure<Hex{名称缩写}{Cmd}{SubId}_S>(data);
    text += QString::fromUtf8("【类型】: {指令名称}\n");
    // 格式化输出字段值
    text += QString::fromUtf8("CRC16:    0x%1\n").arg(packet.Crc16, 4, 16, QChar('0')).toUpper();
    break;
}
```

## 5. 命名规范

### 5.1 结构体命名

| 规则 | 示例 |
|------|------|
| Hex{名称缩写}{Cmd}{SubId}_S | HexPPS0012_S |
| 名称缩写使用大写 | PPS, IMU, CAN, UART |
| Cmd 和 SubId 使用两位十六进制 | 00, 01, 11, 12 |

### 5.2 变量命名

| 规则 | 示例 |
|------|------|
| 结构体实例使用小写 | `ppsPacket`, `canPacket` |
| 数组名使用复数 | `Acceleration`, `Reserved` |
| 布尔值使用 is/has 前缀 | `IsValid`, `CtrlStatus` |

### 5.3 注释规范

| 规则 | 示例 |
|------|------|
| 结构体上方添加 `/* 指令名称 CmdSubId */` | `/* PPS开关控制 0012 */` |
| 字段使用 `///` 注释 | `///< PPS开关状态 0:关闭 1:开启` |
| case 语句添加注释 | `case 0x12: /* PPS开关控制 */` |

## 6. 常见错误与排查

### 6.1 错误分类

| 错误类型 | 表现 | 常见原因 |
|----------|------|----------|
| 编译错误 | 结构体未定义 | 忘记在 DataParser.h 中定义 |
| 运行时退出 | 程序启动后立即退出 | SubId 使用了十进制 |
| 指令不匹配 | 发送后无响应 | case 值与注册的 subId 不一致 |
| 数据解析错误 | 显示数据异常 | 结构体字段顺序/大小与协议不一致 |

### 6.2 排查清单

```
□ 检查所有 case 语句是否使用十六进制（如 case 0x11）
□ 检查 initCommands() 中 subId 是否使用十六进制（如 0x11）
□ 检查结构体字段顺序是否与协议文档一致
□ 检查结构体字段类型和长度是否与协议文档一致
□ 检查 CRC16 字段是否在最后
□ 检查是否包含 user_head_t head 字段
□ 检查是否使用 #pragma pack(push, 1)
```

### 7.1 修改记录

当协议文档更新时，需记录以下信息：

| 修改日期 | 修改内容 | 影响文件 |
|----------|----------|----------|
| 2026-07-16 | 新增 PPS开关控制指令 | DataParser.h, CommandViewModel.cpp |

| ... | ... | ... |

### 7.2 兼容性处理

- 新增指令：按标准流程添加，不影响现有功能
- 修改指令：检查是否需要保留旧版本兼容
- 删除指令：标记为废弃，保留代码但不再注册

## 9. 注意事项

1. **十六进制一致性**：所有 SubId 必须使用十六进制表示（如 `0x11`），**禁止使用十进制**（如 `17`）
2. **结构体对齐**：使用 `#pragma pack(push, 1)` 确保字节对齐
3. **字段顺序**：结构体字段顺序必须与协议文档一致
4. **字节序**：协议使用小端格式，注意多字节字段的解析
5. **预留字段**：发送时填0，接收时可显示为十六进制
6. **CRC16**：回复数据中包含 CRC16 校验，需验证或显示
7. **编译验证**：每次修改后必须编译运行验证
