# 921600 波特率串口丢字节排查报告（2026-10-23）

## 一、测试现象

- 上位机以 **921600bps** 与设备通信时丢字节：帧 CRC16 校验失败、"干净丢失"
  （整字节消失，无半字节/噪声特征），且**偏向帧后段字节**
- 特征性极强的表象：**"老固件正常、新固件丢"**，但两版间 USART0 ISR 源码未变
- 115200bps 下同一固件完全正常

## 二、字节时间预算（定位的前提）

| 波特率 | 每字节时间 | RX 中断预算 | 结论 |
|--------|-----------|------------|------|
| 921600 | **10.86µs** | 12µs（4字节FIFO缓冲） | 任何 >10µs 的中断推迟都可能 ORE 丢字节 |
| 115200 | 86.8µs | 174µs | 各类抖动均免疫，无法用于复现 |

921600 下的核心矛盾：**RX 中断被推迟超过一个字节时间 → 硬件 ORE（overrun）→
干净的整字节丢失**。排查目标即"谁推迟了 RX 中断"。

## 三、五层排查（按发现顺序，逐层收窄）

### 层1：编译优化等级 -O0（放大器，非唯一根因）

- **现象**：ISR 源码未变，"老固件正常新固件丢" → 优先查工程设置而非源码
- **根因**：-O0 使 USART0 ISR 膨胀到 **10~20µs**，单独就足以超过 12µs 字节预算
- **修复**：编译优化等级必须 **-O1 及以上**
- **教训**：-O0 是放大器而非唯一根因——升到 -O1 后丢包率下降但未归零，
  说明还有别的推迟源

### 层2：USART0 双 TX 路径交织（独立的 TX 侧问题，排查中顺带发现）

- **现象**：上位机日志出现乱码前缀、AT 应答 "OK" 丢失
- **根因**：存在两条并发 TX 路径——`fputc` 直写 DATA 寄存器 +
  TBE 中断驱动的环形缓冲，两者同时发送时**字节交织**
- **修复**：printf 一律重定向到 `uart0_send_buf` 环形缓冲**单一路径**
- **重要经验（351 项目验证）**：**回显法测得的丢失率 ≠ RX 丢失率**——
  TX 侧还在丢，必须先把 TX 收敛到单一路径，才能用回显法可信地度量 RX

### 层3：指令解析任务挂入分频门控（独立的队列溢出问题）

- **现象**：指令偶发丢失、队列溢出
- **根因**：指令解析曾挂在 100Hz 分频门控内——921600bps 下 **10ms 涌入约
  921 字节**，超过 512 深度的接收队列 → 硬件级溢出
- **修复**：**串口接收队列必须每拍（1ms）排空**；指令解析严禁挂入分频门控

### 层4：ISR 中满态重置队列索引（独立的字节错位问题）

- **现象**：偶发整帧 CRC16 错误
- **根因**：ISR 在队列满时重置写索引（front），与主循环 `BspDeQueue` 并发
  改写同一索引 → **字节错位**（丢的不止一个字节，整帧错位）
- **修复**：ISR 满时**直接丢弃新字节**即可，禁止满态重置索引

### 层5（真凶）：SysTick 调用链中的 64 位软件除法

排除以上四层后丢包仍未归零，最终定位：

```text
SysTick_Handler (优先级0, 1kHz)
  └─ BspSysTickMs()
       └─ G_UsTimeSource()                      ← 时基源注入调用
            └─ dwt_us_from_cycles32()
                 └─ 64位除法 (__aeabi_uldivmod)  ← ★ 真凶
```

- **根因**：Cortex-M3 **无硬件除法**，`__aeabi_uldivmod`（64 位软件除法）
  耗时约 **1.5~3µs+**；SysTick（优先级 0）执行期间把 USART0 RX 中断
  （优先级 1）推迟——推迟量逼近字节时间 10.86µs → 偶发 ORE 干净丢字节
- **定量吻合**：丢失率 ≈ SysTick 窗口 / 1ms ≈ **0.3%/字节**，与实测一致
- **修复**：`dwt.h`/`dwt.c` 中 64 位除法改为 **32 位除法**——
  `Fcpu/1e6 = 108`（108MHz 主频）恰好整除，换算因子可在编译期算出，
  32 位除法与 64 位版本**数值精确等价**（参照知识库 IMU_303_351 修复报告）
- **验证**：**72540 字节连续收发零丢失**

## 四、防御规范（后续约束）

1. **中断路径（含中断调用的任何函数链）禁止**：
   - 64 位除法/取模（`__aeabi_uldivmod` 每次吞掉 1.5~3µs+）
   - `printf` / 浮点格式化（软浮点 `%f` 每帧数百 µs）
   - `double` 运算（软浮点库，单次数十 µs 起）
2. 串口接收队列**每拍排空**；指令解析严禁挂入分频门控
3. ISR 队列满时**丢弃新字节**，禁止满态重置索引
4. printf 统一走环形缓冲单一路径，禁止 fputc 直写 DATA 寄存器
5. 编译优化等级保持 **-O1 及以上**；"老固件正常新固件丢"且 ISR 源码未变时，
   优先查工程 Optim 设置
6. 度量 RX 丢失率前先确认 TX 单一路径，否则回显法结果不可信
